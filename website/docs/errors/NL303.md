# NL303: member not found on this type

After a dot, N# knows the receiver's type and can enumerate its members. NL303 is what it reports
when the name you asked for is not one of them. The receiver itself resolved — that is what
separates this code from [NL301](./NL301.md), which fires when the thing *before* the dot is
unknown.

```n#
class User {
    Name: string
}

func Describe(u: User): string {
    return u.Nme          // ERROR NL303
}
```

```text
── [NL303] ERROR ──────────────────────────── Program.nl:6:14 ──

    6 |     return u.Nme          // ERROR NL303
      |              ^^^

Member 'Nme' not found on type 'User'

I cannot find a member called `Nme` on type `User`:

Hint: The type `User` does not have a member named `Nme`.
Check for typos, or make sure you're accessing the right type.

Suggestion: Name
```

The diagnostic underlines the member name rather than the whole `u.Nme` expression, and the
suggestion is drawn from the members `User` actually has.

## Why is this an error?

N# resolves members statically. There is no dynamic fallback that could find `Nme` later, so a
member access that does not bind is a program with a hole in it. Reporting it at the name also keeps
the mistake attributable: one diagnostic where you typed it, rather than a type error further up the
expression once the failed access has been given some placeholder type.

## How to fix it

```n#
class User {
    Name: string
}

func Describe(u: User): string {
    return u.Name
}
```

## Where else NL303 shows up

It is one rule, asked in several places:

- **Members of external types.** `s.Lenght` on a `string` reports `Member 'Lenght' not found on type
  'string'` and suggests `Length` — the member list comes from reflection over the referenced
  assembly, so BCL typos get the same treatment as your own.
- **Object initializer member names.** `new User { Nam: "x" }` reports NL303 on `Nam`.
- **Union cases and their payloads.** `new Shape.Crcle { radius: 1.0 }` reports the case name, and
  `new Shape.Circle { radus: 1.0 }` reports the payload member — both as NL303.

## Two neighbours it is worth telling apart

- A member that **exists** but is not exported from another package is `NL308`, not NL303. N# spells
  visibility by case — PascalCase exports, camelCase stays inside its package — so `service.summaries`
  read from a file in a different namespace is a *visibility* failure. The member was found; saying
  "not found" would send you looking for a typo that isn't there.
- A **method name written without parentheses** — `items.Clear` used as a value — is [NL411](./NL411.md). Again
  the member was found; it is being read as a value instead of called.
