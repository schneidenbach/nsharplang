# NL935: an attribute written at a position N# has no attribute for

Every attribute in N# is written directly on the declaration it belongs to. There is no attribute
**target** prefix — C#'s `[return: ...]`, `[assembly: ...]`, `[field: ...]`, `[param: ...]` — and no
attribute position on an **enum member**.

Writing one is reported once, at the attribute, and the declaration around it still parses. Before
this code existed, `[return: Mark]` was read as an attribute named `return` and produced four
diagnostics, none of which named the real problem.

```n#
import System

class MarkAttribute: Attribute {
    constructor() {
    }
}

class Target {
    [return: Mark]              // ERROR NL935
    func Answer(): int {
        return 1
    }
}

enum Level {
    [Mark]                      // ERROR NL935
    Low = 1,
    High = 2
}
```

```text
── [NL935] ERROR ──────────────────────────── Program.nl:10:6 ──

    10 |     [return: Mark]              // ERROR NL935
       |      ^^^^^^

N# has no 'return:' attribute position — an attribute is written on the declaration it belongs to

Suggestion: Remove the 'return:' prefix, or move the attribute onto a declaration that can carry one.
```

```text
── [NL935] ERROR ──────────────────────────── Program.nl:17:5 ──

    17 |     [Mark]                      // ERROR NL935
       |     ^

N# has no attribute position on an enum member

Suggestion: Write the attribute on the enum declaration itself, or model the per-member data as a
lookup the program owns.
```

## How to fix it

**A target prefix.** Drop the prefix and write the attribute where it belongs. A method's attributes
go on the method; a field's go on the field; a parameter's go inside the parameter list:

```n#
class Target {
    [Mark]
    func Answer(): int {
        return 1
    }

    func WithParameter([Mark] value: int): int {
        return value
    }
}
```

There is no N# spelling that reaches a method's **return value** or an **assembly**. A return-value
annotation that an external framework reads has to come from somewhere else — a wrapper type, or a
declaration-level attribute the framework also understands.

**An enum member.** Attributes that describe individual enum members — a display name, a serialized
spelling — are usually read reflectively by a framework. Carry the data in the program instead, where
it is ordinary code that the compiler checks:

```n#
enum Level {
    Low = 1,
    High = 2
}

func DisplayNameOf(level: Level): string {
    if level == Level.High {
        return "High priority"
    }

    return "Low priority"
}
```

## Why the position does not exist

An attribute's position is not only syntax: it decides which metadata row the attribute is written
into, and every row N# writes has a declaration the language can name. A return value and an assembly
have no declaration in N#'s grammar at all. An enum member has one, but an enum's members become
literal fields of a type that is finalized before any attribute in the program has been bound, so
there is no point at which an attribute on one could be attached. Rather than accept the syntax and
drop it — which is what a silently-ignored attribute amounts to — the position is refused where it is
written.
