# NL338: an event declared over a type that is not a delegate

An event's type is the **handler** a subscriber attaches, so it has to be a delegate. A type that is
not one has no `Invoke` signature to give a handler lambda, no accessor signature to emit, and no
`EventInfo` the CLR would accept.

```n#
class Widget {
    event Changed: int          // ERROR NL338
}
```

```text
── [NL338] ERROR ────────────────────────────────── Program.nl:4:11 ──

    4 |     event Changed: int          // ERROR NL338
      |           ^^^^^^^

'Changed' is declared as an event, but 'int' is not a delegate type

Suggestion: An event's type is the handler a subscriber attaches, so it must be a delegate —
`EventHandler`, `EventHandler<T>`, or an `Action`/`Func` shape. Drop the `event` word if you meant
an ordinary field.
```

The squiggle goes under the event's **name**: that is the member being declared, and it is what the
reader is looking at when they ask what went wrong.

## How to fix it

**Name a delegate.** `EventHandler` is the .NET convention for an event with no payload;
`EventHandler<T>` carries one.

```n#
import System

class Widget {
    event Changed: EventHandler
}
```

An `Action` or `Func` shape works too, and is what you want when the handler's signature is not the
`(sender, args)` pair:

```n#
import System

class Progress {
    event Reported: Action<int>
}
```

**Or drop `event`.** If you meant an ordinary field that happens to hold a value, remove the keyword:

```n#
class Widget {
    Changed: int
}
```

A field can be a delegate too — `Handler: Action<int>` is an ordinary member that `+=` and `-=`
combine and remove. The difference is that a **field** can be read, written and invoked by anyone
who can see it, while an **event** may only be subscribed to from outside the declaring type.
