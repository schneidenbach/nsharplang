# NL347: one interface slot implemented explicitly twice

An interface declares each member once, so it has one slot per member and one implementation per slot.
NL347 is two explicit implementations naming the same slot.

It fires on the case nothing else in the compiler can see: two **different spellings** of one
interface. Two members written with the *same* name are already
[NL306](./NL306.md), whatever those names are, so that case is left to it rather than reported twice.

```n#
namespace Sample

interface IPing {
    func Ping(): int
}

class Probe: IPing {
    func IPing.Ping(): int => 1
    func Sample.IPing.Ping(): int => 2        // ERROR NL347
}
```

```text
── [NL347] ERROR ─────────────────────────── Program.nl:9:5 ──

    9 |     func Sample.IPing.Ping(): int => 2        // ERROR NL347
      |     ^^^^^^^^^^^^^^^^^^^^^^^

'Probe' implements the interface member 'Ping' of 'IPing' explicitly more than once

Suggestion: Keep one of them. A slot has one implementation, and two spellings of the same interface — with and without its namespace — name the same slot rather than two.
```

## Why is this an error?

`IPing` and `Sample.IPing` are two member NAMES and one interface member. Without this rule the two
declarations would both emit, both write a `MethodImpl` row for the same slot, and the type would fail
to load — with a message naming a slot rather than either line that caused it.

## How to fix it

Keep one. An explicit implementation is not an overload: the interface declares the member once, so
there is nothing for a second declaration to distinguish itself by.
