# NL002: a name is used without the import that provides it

NL002 is the compiler telling you which `import` supplies a name you wrote. It is **not a claim that
the name could not be resolved** — N# binds a metadata type by its simple name whether or not the
import is there — so this is import *hygiene*. When it fires, the fix is one line and the diagnostic
writes it for you.

```n#
func Stamp(): string {
    return DateTime.Now.ToString()          // ERROR NL002
}
```

```text
── [NL002] ERROR ──────────────────────────── Program.nl:2:12 ──

    2 |     return DateTime.Now.ToString()          // ERROR NL002
      |            ^^^^^^^^

'DateTime' is used without the import that provides it

Suggestion: Add 'import System' at the top of the file
```

The suggestion is the exact line to paste, and the span is on the name, so a file with three of
these tells you three times where to look.

## It is the other reading of [NL010](./NL010.md)'s fact

When a simple name resolves, the namespace that supplied it is known exactly: it is the prefix that,
together with the spelling you wrote, spells the resolved type's full name.

- If the file **imports** that namespace, the import is used and NL010 stays quiet about it.
- If the file **does not**, the name was written without the import that provides it, and this rule
  speaks.

One measurement, two readings — so the two rules cannot disagree about what an import supplies. They
used to, and the census found it in one name: `OperatingSystem.IsWindows()` written with no
`import System` was accepted in silence, while the same file *with* the import had NL010 report the
import dead. Both rules answered from hand-written tables of BCL spellings, and `OperatingSystem` was
in neither.

## There is no whitelist

The rule used to carry two: a 25-name list for a bare identifier and a 16-name list for a written
type. Neither exists now, and neither could have been finished. Any name whose supplying namespace is
not imported is reported, whatever it is called:

```n#
func Check(): bool {
    return OperatingSystem.IsWindows()      // ERROR NL002
}
```

## Why is this an error?

Because the answer is knowable and the cost of guessing is not. A file that leans on implicit binding
reads as though the imports at the top are the whole dependency list when they are not. Naming the
import turns a habit into a one-line paste.

It blocks the build for the same reason the rest of the lint set does: a diagnostic that hands you
the complete fix has no business being advisory.

## N# has no implicit imports

There is no equivalent of C#'s `ImplicitUsings`: nothing is imported on your behalf, per project or
per file. A C# file that writes `List<int>` with no `using System.Collections.Generic;` is relying on
that project setting, and the same file brought across to N# gets NL002 until the import is written
out. That is the intended outcome — the import block is the file's dependency list, and a list that
is partly supplied by a build property is not one.

## How to fix it

Add the import the suggestion names:

```n#
import System

func Stamp(): string {
    return DateTime.Now.ToString()
}
```

## When N# stays quiet

- **A name that resolved to something other than a metadata type.** A local, a parameter, a member, a
  type parameter, a source declaration — none of them needs an import, so none of them is recorded as
  needing one.
- **A source type from another namespace of the same project.** Project-wide discovery resolves it
  with no import at all; that is the language's rule, and demanding one would make working programs
  unbuildable.
- **A name your own project declares.** A spelling the project declares is never a missing import,
  whatever a referenced assembly happens to call its own types.
- **A member of the enclosing type.** A class with its own field called `DateTime` can write
  `DateTime` freely: the rule checks the type's own members before it reports a bare identifier.
- **An already-imported namespace**, naturally, and a name brought in by a **file import**.
- **A file that was not analysed.** The rule reads a binding fact; a file that was never bound has
  none, and silence is the honest answer.

## It is a fully qualified spelling's opposite number

Writing the whole path resolves without any import, so a fully qualified name draws no NL002 — and,
symmetrically, keeps no import alive. `System.Text.StringBuilder` needs nothing and uses nothing.

## Every site carries its own fix

Each mention is reported separately: two `DateTime.Now` calls give two NL002s, one per line, and the
IDE quick fix is offered on each, anchored on the name the message names rather than on whatever
syntax encloses it.
