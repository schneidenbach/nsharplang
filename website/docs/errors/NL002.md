# NL002: a known name is used without its import

NL002 is the compiler recognising a name from the .NET base library and telling you which `import`
supplies it. It is a small, deliberate whitelist — about twenty-five names — not an analysis of
every unresolved identifier, and **not a claim that the name could not be resolved**: N# binds BCL
simple names without an import, so this is import *hygiene*. When it fires, the fix is one line and
the diagnostic writes it for you.

```n#
func Stamp(): string {
    return DateTime.Now.ToString()          // ERROR NL002
}
```

```text
── [NL002] ERROR ──────────────────────────── Program.nl:2:12 ──

    2 |     return DateTime.Now.ToString()          // ERROR NL002
      |            ^^^^^^^^

'DateTime' is used without the import that provides it

Suggestion: Add 'import System' at the top of the file
```

The suggestion is the exact line to paste, and the span is on the name, so a file with three of
these tells you three times where to look.

## Why is this an error?

Because the answer is knowable and the cost of guessing is not. `DateTime`, `List`, `Regex`,
`HttpClient` and the rest are names people write from memory in a new file, and a file that leans on
implicit binding for them reads as though the imports at the top are the whole dependency list when
they are not. Naming the import turns a habit into a one-line paste.

It blocks the build for the same reason the rest of the lint set does: a diagnostic that hands you
the complete fix has no business being advisory.

## What it does *not* say

**It does not say the name could not be found.** The sentence used to read "I can't find
'StringBuilder'", even though the compiler could resolve that name without its import.

The product contracts use each of these names as a parameter type, box its value to `object`, and
test that object for null. With NL002 silenced, all fifteen programs build both with and without
their suggested namespace imports:

- `StringBuilder`, `Task`, `CancellationToken`, `List<int>`, `Dictionary<string, int>`,
  `HashSet<int>`, `Stack<int>` and `Stream`;
- `Regex`, `HttpClient`, `Queue<int>`, `LinkedList<int>`, `File`, `JsonSerializer` and `Encoding`.

The second group used to fail during emission. Broader external-type admission made those shapes
build; adding an import was never the fix for their backend declines. These probes measure their
specific parameter-and-boxing shape, not every constructor or member call on those types.

NL002 states the import hygiene fact: the name is used and its providing namespace is not imported.
`tests/native/diagnostic-honesty` builds all fifteen pairs on every gate, checks both child exit
codes, and compares the complete diagnostic streams.

## How to fix it

Add the import the suggestion names:

```n#
import System

func Stamp(): string {
    return DateTime.Now.ToString()
}
```

## When N# stays quiet

The rule is a whitelist, and everything outside it is silence — "I have not heard of this name" is
not evidence of a missing import, so the rule declines to guess:

- **A name the table does not carry says nothing.** A file calling `Stopwatch.StartNew()` with no
  `import System.Diagnostics` draws no NL002 at all, and compiles. This rule is a convenience for the
  names people write most often, not a general unresolved-name check — the linter has no type
  universe to consult, so outside the table it has nothing it could honestly say.
- **A member of the enclosing type wins.** A class with its own field called `DateTime` can write
  `DateTime` freely; the rule checks the type's own members before it consults the table.
- **An already-imported namespace is silent**, naturally, and so is a name brought in by a file
  import.

## The two tables are not the same

A bare identifier and a `new` are answered by different lists, and the difference is deliberate.
Sixteen names are answered in both positions:

`List`, `Dictionary`, `HashSet`, `Queue`, `Stack`, `LinkedList`, `StringBuilder`, `Regex`, `File`,
`Directory`, `Path`, `Stream`, `HttpClient`, `JsonSerializer`, `Task`, `CancellationToken`.

Nine more are answered only when written as a bare identifier — `Encoding`, `DateTime`, `TimeSpan`,
`Guid`, `Uri`, `Tuple`, `Lazy`, `Action`, `Func` — because those are names a file uses as a static
receiver rather than constructs. `DateTime.Now` is reported; `new Guid()` is not the way that name
gets used, so demanding an import there would be noise.

Each mention is reported separately: two `DateTime.Now` calls give two NL002s, one per line, so
every site carries its own fix.
