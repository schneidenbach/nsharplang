# NL334: an `async` lambda whose target returns no task

An `async` lambda's body produces the **result** its target delegate's task carries: write
`async () => 42` where a `Func<Task<int>>` is expected and the `42` becomes the task's value. That
only works when the target returns a task-like type — `Task`, `Task<T>`, `ValueTask` or
`ValueTask<T>`. NL334 reports a target that returns anything else, and a lambda with no target at all.

```n#
import System

func Build() {
    compute: Func<int> = async () => 42        // ERROR NL334
    print compute()
}
```

```text
── [NL334] ERROR ────────────────────────────────── Program.nl:4:26 ──

    4 |     compute: Func<int> = async () => 42        // ERROR NL334
      |                          ^^^^^

An 'async' lambda produces a task, but this delegate returns 'int'

Suggestion: An `async` body's value is wrapped in the task the delegate returns. Change the target to
return `Task`, `Task<T>`, `ValueTask` or `ValueTask<T>`, or drop the `async` keyword and return the
value directly.
```

A `:=` declaration names no delegate type, so it names no task either:

```n#
func Build() {
    compute := async () => 42                  // ERROR NL334
    print compute
}
```

```text
An 'async' lambda produces a task, and nothing here names the delegate type it should produce one of
```

## No `async void`

C# allows an `async` lambda on a `void`-returning delegate (`Action`), where the body runs
fire-and-forget and an exception it raises is posted to the synchronization context. **N# does not.**
N#'s `await` is lowered synchronously — there is no state machine — so an async body with nowhere to
put its task is exactly its own body: the keyword would change nothing, and an exception would reach
the caller rather than a task. Rather than accept a keyword that means nothing, N# reports NL334 and
tells you to drop it.

Refusing it also keeps overload resolution honest. `Task.Run` declares `Action` beside `Func<Task>`;
if an `async` lambda could be an `Action`, `Task.Run(async () => …)` would bind to the fire-and-forget
overload and silently discard what the body awaited.

## An event handler is the common case

Nearly every .NET event's delegate returns `void`, so an `async` handler is NL334 — and here the
first fix does not exist, because the delegate belongs to whoever declared the event:

```n#
import System
import System.Collections.ObjectModel
import System.Threading.Tasks

class Watcher {
    async func SaveAsync(): Task {
        await Task.Delay(1)
    }

    func Watch(items: ObservableCollection<string>) {
        sub := on items.CollectionChanged async (sender, args) => await SaveAsync()   // ERROR NL334
        off sub
    }
}
```

```text
An 'async' lambda produces a task, but this event's handler returns 'void'

Suggestion: An event's delegate is the one that declared it, so there is no `async` handler to write.
Start the work inside an ordinary handler and discard the task — `on x.E (sender, args) => { _ =
RunAsync() }` — or call a `void` method that does the awaiting.
```

Start the work and discard the task. The discard is the point: it is visible in the source, so
nobody reads the handler as if it waited.

```n#
func Watch(items: ObservableCollection<string>) {
    sub := on items.CollectionChanged (sender, args) => {
        _ = SaveAsync()
    }
    off sub
}
```

The task is not awaited, so an exception it raises lands on the task rather than in the handler —
which is exactly what C#'s `async void` handler does differently, and deliberately: `async void`
re-raises on the synchronization context and can tear the process down. If the work must not be lost,
give the handler a `void` method that owns the failure (logging it, or storing it for the next call)
and call that instead.

## How to fix it

**Give the target a task-like return.** This is almost always what you meant: the lambda is
asynchronous, so what it hands back is a task.

```n#
import System
import System.Threading.Tasks

func Build(): int {
    compute: Func<Task<int>> = async () => await Task.FromResult(42)
    return await compute()
}
```

**Or drop the `async`.** A body that awaits nothing does not need the keyword, and `await` is legal
in a non-async body in N# anyway.

```n#
import System

func Build(): int {
    compute: Func<int> = () => 42
    return compute()
}
```
