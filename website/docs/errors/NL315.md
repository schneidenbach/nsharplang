# NL315: a must-use result was discarded

`[MustUse]` marks a function or method whose return value carries the point of calling it — a
validation answer, a status, a value that replaces the receiver. Writing such a call as a bare
statement throws that value away, and N# reports NL315 rather than letting the call look like it did
something.

```n#
[MustUse]
func Validate(name: string): bool {
    return name.Length > 0
}

func Register(name: string) {
    Validate(name)          // ERROR NL315
}
```

The underline is on the **callee name**, not on the whole statement: the name is what tells you
which contract you are breaking.

```text
── [NL315] ERROR ───────────────────────────── Program.nl:7:5 ──

    7 |     Validate(name)          // ERROR NL315
      |     ^^^^^^^^

You're discarding the result of 'Validate', but 'Validate' is marked [MustUse] — its result must be used

Suggestion: Use the result (assign it, return it, or pass it to a call), or discard it explicitly with `_ = ...`.
```

## Why is this an error?

A discarded return value is not always a mistake — a `bool` from a method you called for its side
effect is fine to drop. `[MustUse]` is how an author says "for this one, it is not". The classic shape is a function that
reports failure through its result instead of throwing: ignore the result and the failure disappears
with it, and the call site reads as though the check had been made.

N# does not guess which functions those are. NL315 fires only where somebody wrote the attribute.

## How to fix it

Use the value. Assign it, return it, branch on it, or pass it on:

```n#
[MustUse]
func Validate(name: string): bool {
    return name.Length > 0
}

func Register(name: string): string {
    if !Validate(name) {
        return "rejected"
    }

    return "registered " + name
}
```

If you genuinely do not want the result, say so with the explicit discard. `_ =` is accepted and
silent — it turns "I forgot" into "I decided":

```n#
func Register(name: string) {
    _ = Validate(name)
}
```

## What counts

**The attribute is on the callee, not the type.** A `bool` returned by an unmarked function may be
discarded freely; the same `bool` from a `[MustUse]` one may not. There is no NL315 without the
attribute.

**Methods carry it too**, not just free functions. A `[MustUse]` method called bare inside its own
class is reported at the call, exactly as a free function is.

**Parentheses do not hide the call.** Wrapping the statement changes nothing about what is being
discarded, and the report follows the call rather than the statement's outer shape.
