# NL402: no overload matches this call

The name is overloaded, and none of its overloads accepts this call. N# does not pick a "closest"
one and report the difference — with several candidates in play there is no single signature the
mistake can be measured against, so the diagnostic hands you the whole candidate set instead.

```n#
class Printer {
    func Write(value: int): string {
        return value.ToString()
    }

    func Write(value: bool): string {
        return value.ToString()
    }
}

func Use(printer: Printer): string {
    return printer.Write("text")          // ERROR NL402
}
```

```text
── [NL402] ERROR ─────────────────────────── Program.nl:12:20 ──

    12 |     return printer.Write("text")          // ERROR NL402
       |                    ^^^^^

No overload of 'Write' accepts 1 argument with these types

I cannot find an overload of `Write` that matches this call:

Hint: This call passes 1 argument: `string`.
Available overloads:
  - Write(value: int): string
  - Write(value: bool): string

Check the argument count and types. If you meant to reference the method itself, use it in a context with a delegate type instead of calling it.
```

Read it as two lists. The first line says what you passed — the count and the type of each argument.
The `Available overloads` block says what was on offer, in declaration order, printed with N#
signatures rather than CLR ones.

## Why is this an error?

Overload resolution is the compiler choosing which method body your call means. When nothing scores,
there is no body to check the call against and nothing to emit. N# refuses rather than picking the
nearest candidate and reporting a chain of argument errors against a signature you never intended.

## How to fix it

Either convert the argument to something an existing overload takes, or add the overload:

```n#
class Printer {
    func Write(value: int): string {
        return value.ToString()
    }

    func Write(value: bool): string {
        return value.ToString()
    }

    func Write(value: string): string {
        return value
    }
}

func Use(printer: Printer): string {
    return printer.Write("text")
}
```

## When NL402 appears instead of a plainer error

NL402 needs **two or more** candidates. With exactly one, N# has a specific signature to blame and
uses a sharper code — [NL401](./NL401.md) for the wrong count, [NL202](./NL202.md) for the wrong argument type,
pointing at the argument itself. That is why adding an overload to a working call site can change
the error you get on a *different*, already-broken call to the same name.

The rule covers external methods too. `Math.Max("a", "b")` reports NL402 with the .NET overload set
printed the same way, because N# scores metadata overloads through the same walk it uses for
overloads you declared.

Free functions overload as well as methods do, so a pair of top-level `func Write` declarations
produces exactly the same report as a pair of methods.

## Method groups passed to a delegate parameter

The last sentence of the diagnostic — "If you meant to reference the method itself, use it in a
context with a delegate type instead of calling it" — is about a real second cause. When an
overloaded name is passed *without* parentheses to a parameter whose type is a delegate, and no
overload's shape matches that delegate, the same code is reported against the argument. The fix
there is to match the delegate's parameters and return type, not to change the argument count.
