# NL313: this expression statement has no effect

A statement is a thing a program *does*. An expression that only produces a value — a field read, a
comparison, an arithmetic result — does nothing at all when its value is thrown away. NL313 is N#
refusing to compile the line rather than compiling it into no instructions.

```n#
class Box {
    Value: int
}

func Go(b: Box) {
    b.Value          // ERROR NL313
}
```

```text
── [NL313] ERROR ───────────────────────────── Program.nl:6:7 ──

    6 |     b.Value          // ERROR NL313
      |       ^^^^^

This expression statement has no effect

This expression is written as a statement, but it does not do anything by itself:

Hint: The expression `Value` produces a value or names a member, but the value is ignored.
Only assignments, calls, increments, decrements, await expressions, and object construction can be used as statements.

Suggestion: Use the value by assigning it, printing it, passing it to a call, or remove the expression. If you meant to call a method, add parentheses with the required arguments.
```

The hint names the expression it found, and lists the closed set of expressions that may stand alone
as statements. `b.Value` is not in it, so this line is either an unfinished thought or the remains of
one.

## Why is this an error?

Every line that reads like it does something and does not is a place a reader will stop. Worse, the
common causes are real bugs with a plausible look: a call that lost its parentheses, an assignment
whose `=` did not survive an edit, a comparison that was meant to be a condition. Compiling the line
to nothing hides all three.

## How to fix it

Use the value:

```n#
class Box {
    Value: int
}

func Go(b: Box): int {
    total := b.Value
    return total + 1
}
```

Or, if the value was never wanted, delete the line.

## What may stand alone as a statement

The list in the hint is the whole rule: **assignments, calls, increments, decrements, `await`
expressions, and object construction**. Everything else needs somewhere for its value to go.

So the two lines below differ by exactly one token, and only one of them is a statement:

```n#
b.Value = 1          // an assignment — fine
b.Value              // reports NL313
```

And a comparison written on its own line is NL313, not a type error:

```n#
func Go(n: int) {
    n == 1          // ERROR NL313
}
```

That one is worth knowing: `==` where `=` was meant is a silent no-op in languages that allow it,
and it is the reason this check exists.

## The second form: a for-loop iterator

The third clause of a `for` has the same obligation, and gets the same code with its own sentence,
`This for-loop iterator has no effect`:

```n#
func Go() {
    for i := 0; i < 3; i + 1 {          // ERROR NL313
        print(i)
    }
}
```

`i + 1` computes a number and discards it, so the loop never advances. The suggestion names the
shapes that do advance it — an assignment, a call, an increment or decrement.

## A neighbour it is worth telling apart

A bare **method name** — `items.Clear`, with no parentheses — is [NL411](./NL411.md), not NL313. N# can see that
you named a method rather than a value, so it says that instead, and tells you both ways forward:
call it, or pass it somewhere that expects a delegate.
