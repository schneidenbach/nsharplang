# NL411: a method name used where a value is required

A method name written without parentheses names code, not a value. N# allows exactly one place for
a bare method name — an expression position whose expected type is a delegate — and reports NL411
everywhere else, including the moment a bare name is returned, assigned, concatenated or compared.

```n#
class Greeter {
    func Greet(): string {
        return "hi"
    }
}

func Use(greeter: Greeter): string {
    return greeter.Greet          // ERROR NL411
}
```

```text
── [NL411] ERROR ──────────────────────────── Program.nl:8:12 ──

    8 |     return greeter.Greet          // ERROR NL411
      |            ^^^^^^^^^^^^^

Method 'Greet' must be called or passed to a delegate

`Greet` names a method, not a value:

Hint: Methods need a call site like `name()` before they produce a value.
A bare method name is only valid when the surrounding API expects a delegate.

Suggestion: If you meant to use the result, call `Greet(...)`. If you meant to pass the method itself, pass it to a parameter with a delegate type.
```

The two halves of the suggestion are the two things a bare name can legitimately have meant, and
they are not variations on one fix: calling it produces a `string`, passing it produces a callable.

## Why is this an error?

In .NET a method group is not a first-class value; it becomes one only when a delegate type says
which signature to bind. Without that, `greeter.Greet` has no type — no size, no representation,
nothing to store. Languages that quietly invoke it instead turn a missing `()` into a silent
behaviour change, which is exactly the class of bug N# is built to refuse.

## How to fix it

If you wanted the result, call it:

```n#
class Greeter {
    func Greet(): string {
        return "hi"
    }
}

func Use(greeter: Greeter): string {
    return greeter.Greet()
}
```

## When a bare method name is legal

The check consults the **expected type** at the expression's position before it decides anything. A
delegate-typed target — a parameter, a field, a declared local — accepts the bare name and no NL411
is reported:

```n#
func Render(make: Func<string>): string {
    return make()
}

func Use(greeter: Greeter): string {
    return Render(greeter.Greet)          // no NL411 — `make` is delegate-typed
}
```

This is worth knowing precisely, because the current backend does not yet lower a bare method group
into a delegate: that program clears the analyzer and then stops at [NL103](./NL103.md). Until it
lowers, wrap the call in a lambda, which compiles today and means the same thing:

```n#
func Use(greeter: Greeter): string {
    return Render(() => greeter.Greet())
}
```

## Overloaded names and events

A name with several overloads reaching a delegate-typed target that fits none of them is
[NL402](./NL402.md), not NL411 — the reference itself was legal and the *choice* failed. A .NET
event named outside an `on` or `off` statement is [NL317](./NL317.md), again a different rule: an event is not a
method group and cannot be called at all.

Lambdas are never NL411. The check exempts them explicitly, so `() => greeter.Greet()` is a value
wherever it appears.
