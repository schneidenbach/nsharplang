# NL327: `this` or `base` where there is no current instance

`this` names **the object the current member was called on**. `base` names the same object,
viewed as its base class. Both need there to *be* such an object, and in two places there is
none: inside a `static` member, and inside a top-level function.

```n#
class Dog: Animal {
    static func Describe(): string {
        return this.Name              // ERROR NL327
    }
}

func Speak(): string {
    return base.Speak()               // ERROR NL327
}
```

```text
── [NL327] ERROR ───────────────────────────── Program.nl:3:16 ──

    3 |         return this.Name              // ERROR NL327
      |                ^^^^

'this' cannot be used in a static member

`this` names the object the current member was called on, and `Describe` runs without one:

Hint: A `static` member belongs to the type itself and is called with no object.
Only an instance member — a method, property, indexer or constructor declared without
`static` — has a receiver.

Suggestion: Drop `static` from `Describe`, or use a value the member already has instead of
`this`.
```

## Why is this an error?

A `static` member is reached through the **type**, never through a value: `Dog.Describe()`
passes no object, and the emitted method has no receiver argument for `this` to be. A
top-level function is not a member of any type at all, so there is nothing for it to have been
called on either.

Reporting it here, at the word, is the whole point of the rule. Without it the reference
survives analysis as an unknown value and the mistake only surfaces much later, as a failure to
emit code — a message about the compiler rather than about your code.

## How to fix it

**If the member should act on an object, make it an instance member.** Drop the `static`:

```n#
class Dog: Animal {
    func Describe(): string {
        return this.Name
    }
}
```

**If the member really is static, name the object you mean.** A static member can still work
with values — it just has to be given one:

```n#
class Dog: Animal {
    static func Describe(dog: Dog): string {
        return dog.Name
    }
}
```

**If you meant another member of the same type,** a static member can call other static members
by name, with no `this`:

```n#
class Dog: Animal {
    static DefaultName: string => "dog"

    static func Describe(): string {
        return DefaultName
    }
}
```

## Where the rule applies

The receiver is a fact about the **enclosing member**, so it is the member's own declaration
that decides — not the shape of the expression:

- **A lambda inherits its enclosing member's answer.** `() => this.Name` written inside a
  static method is reported; the same lambda inside an instance method is fine, because a
  lambda compiles to a member of the same type and sees the same receiver.
- **Property and indexer accessors count as members.** `static Name: string => this.value` is
  reported from the expression body just as it would be from a written getter.
- **Constructors have a receiver.** The object exists before the body runs, so `this` and
  `base` are both available inside one — including `base(...)` chaining in the header.
