# NL329: a struct field initializer with no constructor to run in

A `struct`'s instance field initializers run at the start of each of its **declared constructors**.
A struct that declares none — no primary constructor and no written `constructor` — has nothing that
would ever run them, so every value of the type would keep the CLR zero and the initializer would be
code that never executes.

```n#
struct Point {
    X: double = 1.0        // ERROR NL329
    Y: double
}
```

```text
── [NL329] ERROR ───────────────────────────── Program.nl:2:16 ──

    2 |     X: double = 1.0        // ERROR NL329
      |                ^^

A struct field cannot have an initializer

`Point` is a struct, and a struct value can be produced without running any constructor —
`default(Point)`, an array element, an uninitialized field — so the initializer of `X` would
run for some values of `Point` and not for the rest:

Hint: A class always runs a constructor, so its field initializers always run. A struct does
not, which is why N# refuses an initializer here rather than emitting a rule that holds only
sometimes.

Suggestion: Assign `X` in a constructor of `Point`, or make it `static` if the value belongs
to the type rather than to each value.
```

## How to fix it

**Declare a constructor.** The initializers then run at the start of it, ahead of its body, for every
value built through it. `default(Point)` still keeps the CLR zero — it runs no constructor, which is
exactly why the constructor is what the rule asks for.

```n#
struct Point {
    X: double = 1.0
    Y: double

    constructor(y: double) {
        Y = y
    }
}
// new Point(2.0) is (1.0, 2.0); default(Point) is (0.0, 0.0)
```

**Or assign the field in a constructor instead of initializing it**, which makes the value visible at
the site that produces it.

```n#
struct Point {
    X: double
    Y: double

    constructor(x: double, y: double) {
        X = x
        Y = y
    }
}
```

**Or make the value belong to the type.** A `static` field initializer on a struct is fine: it runs
in the type initializer, which every use of the type reaches.

```n#
struct Point {
    static readonly Origin: Point = new Point(0.0, 0.0)

    X: double
    Y: double

    constructor(x: double, y: double) {
        X = x
        Y = y
    }
}
```

**Or use a class.** A class always runs a constructor, so its instance field initializers always
run.

## Where the rule applies

- It applies to `struct`, `readonly struct`, `ref struct` and `record struct` alike — every one of
  them is a value type with a reachable `default`. A **primary constructor** counts as a declared
  constructor, so `struct Point(x: double) { X: double = x }` is fine.
- It applies only to *instance* fields. A `static` field of a struct may have any initializer, and
  behaves exactly as a class's static field does.
- A **class** is unaffected: see [field initializers](../types.md) for what an instance initializer
  does there, and [`NL328`](./NL328.md) for what it may not name.
