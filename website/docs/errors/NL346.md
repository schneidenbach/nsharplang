# NL346: an explicit implementation of a member the interface does not declare

The qualifier of an explicit interface implementation names an interface the type implements, but the
member name after it is not one that interface declares.

```n#
interface IPing {
    func Ping(): int
}

class Probe: IPing {
    func Ping(): int => 1
    func IPing.Pung(): int => 2       // ERROR NL346
}
```

```text
── [NL346] ERROR ─────────────────────────── Program.nl:7:5 ──

    7 |     func IPing.Pung(): int => 2       // ERROR NL346
      |     ^^^^^^^^^^^^^^^^

'IPing' declares no member named 'Pung'

Suggestion: Check the spelling against 'IPing'. An explicit implementation may only name a member the interface itself declares; an inherited one is implemented by naming the interface that declares it.
```

The type above implements `Ping` the ordinary way, so the interface is satisfied and NL346 is the
only report. Written without that member the qualifier mistake ALSO leaves the slot unfilled, and
[NL325](./NL325.md) appears beside it on the class header — two reports for one typo, which is what
you will usually see.

## Why is this an error?

An explicit implementation exists to fill ONE named slot. If the interface has no such slot the member
is unreachable: it is private, it is not a member of the declaring type, and no interface dispatch can
find it — so it would be a method nothing in the program could ever call.

## How to fix it

**Fix the spelling**, which is the usual cause.

**Or name the interface that really declares the member.** A member inherited into an interface still
belongs to the interface that declared it, and that is the one the qualifier names:

```n#
interface IBase {
    func Ping(): int
}

interface IDerived: IBase {
    func Pong(): int
}

class Probe: IDerived {
    func IBase.Ping(): int => 1       // IBase declares it, so IBase names it
    func IDerived.Pong(): int => 2
}
```
