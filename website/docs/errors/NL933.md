# NL933: an attribute applied where its `AttributeUsage` does not allow

Every attribute type says where it may be written. It says it with `[AttributeUsage(...)]` on its own
declaration, and the answer is inherited by attributes that derive from it. An attribute written
somewhere that list excludes is not a harmless extra row in the metadata — it is a statement the
attribute's author explicitly did not make available.

```n#
import System

[AttributeUsage(AttributeTargets.Class)]
class EntityAttribute: Attribute {
}

class Order {
    [Entity]                    // ERROR NL933
    func Total(): int {
        return 0
    }
}
```

```text
── [NL933] ERROR ───────────────────────────── Program.nl:9:6 ──

    9 |     [Entity]                    // ERROR NL933
      |      ^^^^^^

Attribute 'EntityAttribute' cannot be applied to a function — it is declared for classes

Suggestion: Move it to one of those declarations, or widen the attribute's own '[AttributeUsage(...)]'.
```

## How to fix it

Either move the attribute to a declaration it was written for:

```n#
[Entity]
class Order {
    func Total(): int {
        return 0
    }
}
```

…or widen the attribute's own usage, if you own it and meant it to apply more broadly:

```n#
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method)]
class EntityAttribute: Attribute {
}
```

## What counts as a target

The target is the **declaration you wrote the attribute on**, not the member the compiler eventually
emits:

| You wrote it on | The target is |
| --- | --- |
| a class, a record, a union | `Class` |
| a struct, a record struct | `Struct` |
| an interface | `Interface` |
| an enum | `Enum` |
| a function, a method | `Method` |
| a constructor | `Constructor` |
| a field | `Field` |
| a parameter | `Parameter` |
| a property, an indexer | `Property` **or** `Method` |
| a primary constructor's parameter | `Parameter` **or** `Field` |

A property accepts both bits because N# has no attribute position inside accessor braces: a
property's attributes are written once and reach its accessors. That is the same reason
`[MethodImpl]` — which is declared for `Method` and `Constructor` only — may be written on an N#
property.

## A positional constructor parameter is two rows

A primary constructor's parameter declares the constructor's parameter **and** the field it stores
into, and N# has no target prefix to choose between them. So the declaration accepts an attribute
declared for either, and the attribute's own usage decides where it is written: on the parameter
wherever it allows parameters, on the field otherwise.

```n#
import System

[AttributeUsage(AttributeTargets.Class)]
class EntityAttribute: Attribute {
}

record Order([Entity] Total: int = 0) {     // ERROR NL933
}
```

```text
Attribute 'EntityAttribute' cannot be applied to a positional constructor parameter — it is declared for classes

Suggestion: A positional constructor parameter carries its attribute on the parameter when the
attribute allows parameters, and on the field that parameter declares when it allows fields — this
one allows neither. Move it to a declaration it allows, or widen the attribute's own
'[AttributeUsage(...)]'.
```

This error is reported only when the attribute allows **neither** row. `[JsonIgnore]`, declared for
properties and fields, is accepted there and lands on the field; `[FromRoute]`, declared for
parameters, is accepted there and stays on the parameter.

## Attributes with no `[AttributeUsage]`

An attribute type that does not declare one may be written anywhere. That is the CLR's default, and
it is why most attributes never produce this error.
