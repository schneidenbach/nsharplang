# NL337: an event a type declared, touched from outside that type

An `event` is not a field, and outside the type that declared it the difference is the whole point.
The type that owns the event decides **when** it is raised; everybody else may only **subscribe** to
it with `on` and detach with `off`. NL337 reports the uses that would go around that: reading the
event, invoking it, assigning to it, and `+=` / `-=`.

Inside the declaring type the same name reads as the backing delegate — that is what makes
`Changed?.Invoke(this, args)` an ordinary expression there — so this rule is entirely about **where**
the name is written.

```n#
import System

class Widget {
    event Changed: EventHandler

    func Raise() {
        Changed?.Invoke(this, EventArgs.Empty)   // fine: Widget's own code
    }
}

func Watch(widget: Widget) {
    widget.Changed?.Invoke(null, EventArgs.Empty)   // ERROR NL337
}
```

```text
── [NL337] ERROR ────────────────────────────────── Program.nl:13:5 ──

    13 |     widget.Changed?.Invoke(null, EventArgs.Empty)   // ERROR NL337
       |     ^^^^^^^^^^^^^^

'Changed' is an event declared by 'Widget' — outside 'Widget' it can only be subscribed to

Suggestion: Subscribe with `on widget.Changed (sender, args) => { ... }`; the result is a
subscription you can later pass to `off`. Reading or raising 'Changed' is 'Widget''s own business,
so write a method there if callers need to trigger it.
```

## How to fix it

**Subscribe with `on`, detach with `off`.** This is what the name is for outside the declaring type,
and unlike C#'s `+=` it hands you back a handle, so an inline lambda can be detached without your
keeping the delegate.

```n#
func Watch(widget: Widget) {
    subscription := on widget.Changed (sender, args) => { print "changed" }
    // ... later ...
    off subscription
}
```

**Or give the declaring type a method.** If callers genuinely need to make the event fire, that is a
decision the owner should make explicitly:

```n#
class Widget {
    event Changed: EventHandler

    func Touch() {
        Changed?.Invoke(this, EventArgs.Empty)
    }
}
```

## `+=` and `-=` on an event

C# subscribes with `+=` and unsubscribes with `-=`. N# has `on` and `off` instead, and says so at
the position you wrote:

```n#
func Watch(widget: Widget, handler: EventHandler) {
    widget.Changed += handler                  // ERROR NL337
}
```

```text
'Changed' is an event declared by 'Widget' — it can't be subscribed to with '+='

Suggestion: Subscribe with `on widget.Changed (sender, args) => { ... }`; it returns a subscription
you can later pass to `off`.
```

`-=` gets the sentence that matches what you were trying to do — capture the handle when you
subscribe, then `off` it — and `=` is told that an event is not a field to assign.

On a plain `Func` / `Action` field, `+=` and `-=` still combine and remove delegates. The rule is
about events, not about delegates.

## Derived types are outside too

C#'s rule, kept: only the declaring type's own code reads the backing delegate. A derived class
subscribes to its base's event like any other caller, and raises it by calling a method the base
declared for that purpose.
