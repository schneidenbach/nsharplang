# NL923: a reference assembly could not be loaded

A referenced assembly could not be loaded, and names went unresolved in the same run. NL923 is the
one diagnostic in N# that is **always a warning and never blocks a build** — its whole purpose is to
stop a broken reference from masquerading as a typo.

The reference is declared in `project.yml`:

```yaml title="project.yml"
name: PNL923
version: 1.0.0
outputType: library
targetFramework: net10.0

dependencies:
  - dll: ./Analytics.dll
```

The file it points at is not an assembly at all — this is the whole of it:

```text title="Analytics.dll"
this is not a managed assembly
```

```n#
func Describe(): string {          // ERROR NL923
    return analytics          // ERROR NL301
}
```

```text
── [NL923] WARNING ─────────────────────────── Program.nl:1:1 ──

    1 | func Describe(): string {          // ERROR NL923
      | ^^^^

Reference assembly '/private/tmp/nsharp-agent-wt/probe-fix/run/NL923/./Analytics.dll' could not be loaded or fully inspected (BadImageFormatException: Unknown file format.); types from it may be reported as not found.

── [NL301] ERROR ──────────────────────────── Program.nl:2:12 ──

    2 |     return analytics          // ERROR NL301
      |            ^^^^^^^^^

Variable 'analytics' not found

I cannot find a `analytics` variable on line 2:

Hint: Make sure you've declared this variable before using it.
```

The path in the message is the one your project resolved, so it will differ from the one above.

## Why is this a warning, and why does it appear at all?

Consider what you would see without it. `Analytics.dll` fails to load, so every type it defines is
unknown, so every use of one is "not found" — and you spend an afternoon checking spelling and
imports for names that are spelled correctly. The unresolved-name errors are true and completely
misleading. NL923 supplies the missing sentence: *the reference is broken, start there.*

It is a warning rather than an error because it is **advice about other diagnostics**, not a fault
of its own. Making it block the build would mean a project with a genuinely optional reference could
not compile at all.

## When it appears

NL923 is deliberately quiet. It is reported only when **both** are true in the same run:

1. a reference assembly failed to load or could not be fully inspected, and
2. that analysis also produced an unresolved-name error — `NL201` for a type, `NL301` for a name in
   expression position.

A healthy compilation stays silent even if a best-effort probe failed somewhere, because a warning
about a reference nothing needed would be noise. And a broken reference alone, with everything still
resolving, says nothing either: nothing is wrong that you can observe.

## How to fix it

Fix the reference, not the names. The message names the file and the underlying failure —
`BadImageFormatException` means the file is not a managed assembly at all (a text file, an HTML
error page saved by a failed download, a native library, or a truncated artifact); a missing-file
error means the path in `project.yml` is wrong.

Once the assembly loads, the unresolved names resolve with it and both diagnostics disappear
together. If they do not, the remaining ones are real and you now know they are worth investigating.

## Related

- `NL201` — a type name that resolves to nothing, the error NL923 most often accompanies.
- `NL301` — a name in expression position that resolves to nothing.
- `NL701` — an `import` that resolves to nothing, which is about N# source rather than a compiled
  reference.
