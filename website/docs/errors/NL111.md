# NL111: expression nested too deeply

N# reads an expression **512 levels deep**. Past that, the compiler stops and says so.

This is one of two diagnostics on this site with no example you can read: reproducing it takes a
generated source — 512 nested parentheses inside a `return`, or a chain of more than 512 operators —
which is a thousand characters of nothing. This example is real output, produced from a generated
source by `tests/native/cli-command-contracts/CliCommandContracts.tests.nl`:

```text title="NL111 generated-source output"
-- ERROR --------------------------------------------------  Program.nl

Expression nested more than 512 levels deep

This expression nests more than 512 levels deep, which is deeper than N# reads. Every
stage that reads an expression — the parser, the linter, the formatter and the type
checker — walks it one level at a time, so a tree this deep is a limit on the compiler,
not a judgement about your program.

Hint: Give part of the expression a name with `:=` and use the name here: a long chain
of `||`, `&&` or `+` split into a few named values is both shallower and easier to read.
The deepest expression measured in any real N# source is 70 levels, so a tree past 512
is almost always generated code.

Read more: https://schneidenbach.github.io/nsharplang/docs/errors/NL111
```

## Why is this an error?

Every stage of the toolchain reads an expression by walking it one level at a time — the parser, the
linter, the formatter, the type checker. Depth is therefore a multiplier on the call stack, and a
deep enough expression exhausts it. Before this diagnostic existed, `nlc check`, `nlc build`,
`nlc lint` and `nlc format` all died on such a file with a bare `Stack overflow.` and exit status
134: no code, no file name, no line. A compiler that crashes on its input cannot tell you why.

The limit is a real bound, not a truncation. Nothing is silently dropped or partially compiled: the
file is refused, with a position.

## What counts as a level

Two things make an expression deeper:

- **Nesting into another expression** — a parenthesis, a lambda body, a call argument, an index.
- **Adding one more operand to a chain** — `a || b || c` is three operands and two levels, because
  `a || b` is the left operand of the second `||`.

The expression a statement starts with is level 1, so `return (…)` nested 512 parentheses deep is the
first shape refused.

The count is an **upper bound** on the tree's depth. It is exact for plain nesting and for a chain of
a single operator; where a chain mixes precedences — `w == "a" || w == "b" || …` — each operator is
counted rather than each level, so such a source is refused at roughly half the stated depth. The
margin is still wide: the deepest expression in the N# compiler's own 412,000 lines is **8** levels,
and the deepest in a large machine-converted corpus is **70**.

## How to fix it

Name the parts:

```n#
func IsKeyword(word: string): bool {
    declarations := word == "func" || word == "class" || word == "struct"
    members := word == "field" || word == "property"
    return declarations || members
}
```

This is the same fix whether the depth came from parentheses, from a chain of operators, or from
nested lambdas, and it is worth doing to the source regardless of the limit.

If the file is generated, the generator is the place to fix it — emit intermediate locals rather
than one expression.
