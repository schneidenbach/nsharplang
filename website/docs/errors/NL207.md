# NL207: a type-argument list the type cannot take

A generic declaration fixes how many type arguments its name takes, and a non-generic
declaration takes none. NL207 is the report when the list you wrote does not fit the
declaration — too few, too many, absent where the type needs them, or present on a name that
has no type parameters at all. It is about the *shape* of the argument list; whether the
arguments themselves are legal is [NL208](./NL208.md).

```n#
class Pair<A, B> {
    First: A
    Second: B
}

func FirstOf(p: Pair<int>): int {          // ERROR NL207
    return p.First
}
```

```text
── [NL207] ERROR ──────────────────────────── Program.nl:6:17 ──

    6 | func FirstOf(p: Pair<int>): int {          // ERROR NL207
      |                 ^^^^

Generic type 'Pair' takes 2 type argument(s), but 1 were provided

Suggestion: Match the declaration's type parameter count for 'Pair'
```

The caret covers the head — `Pair` — rather than the argument list, because the head is what
determines the count. The message states the declaration's count first and yours second, in
that order.

## Why is this an error?

`Pair<A, B>` has two type parameters, and every field, method and constructor inside it is
written in terms of both. `Pair<int>` names no type for `B`, so there is no `Second` to speak
of and no way to lay the type out. Unlike a missing function argument, there is no default to
fall back on: a type parameter left unnamed leaves the type itself incomplete.

## How to fix it

Supply one argument per type parameter, in declaration order:

```n#
class Pair<A, B> {
    First: A
    Second: B
}

func FirstOf(p: Pair<int, string>): int {
    return p.First
}
```

## The four shapes

Each prints its own sentence, and the sentence tells you which of the four you hit.

**The wrong count on a generic type.** Too few or too many, in any written type position:

```text
Generic type 'Pair' takes 2 type argument(s), but 1 were provided
Generic type 'Box' takes 1 type argument(s), but 2 were provided
```

**Type arguments on a name that is not generic.** The suggestion is just to delete them:

```text
'Order' is not generic, but 1 type argument(s) were provided

Suggestion: Remove the type arguments: 'Order'
```

**A generic constructed with no argument list at all.** `new Pair { First: 1, Second: 2 }` is a
distinct report with a distinct wording, because the fix is to add rather than to correct:

```text
Generic type 'Pair' requires 2 type argument(s)

Suggestion: Specify them explicitly: 'new Pair<...>(...)'
```

This one arrives with a cascade. Every member in the initializer is then checked against a bare
type parameter, so an `int` written for a field of type `A` produces an [NL202](./NL202.md)
reading `'First' is typed as 'A', but the value is 'int'`. Those go away with the NL207.

**An anonymous union with more than two arms.** An anonymous union type is written as its arms
separated by `|`. Three arms is one too many for v1, and NL207 is what says so — the caret
covers the whole union rather than the surplus arm:

```text
Anonymous union types support exactly two arms in v1; this union has 3 arms.

Suggestion: Declare a named `union` for larger variants.
```

## The head is resolved first

If the head itself does not exist, you get [NL201](./NL201.md) and no NL207 — `Bag<int>` where
there is no `Bag` reports *Type 'Bag' not found* with the caret on `Bag`, and the argument list
is never counted. That ordering is the useful one: a count can only be checked against a
declaration, so there is nothing NL207 could add until the head resolves.
