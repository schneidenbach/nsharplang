# NL701: import path not found

A file import names a path, and N# resolves that path before anything else in the file is looked
at. NL701 is the resolution failing: no file exists where the import points. Nothing else about the
import is examined — the compiler never got as far as reading a file, so it cannot tell you what the
import would have brought in.

```n#
import "./formatting.nl"          // ERROR NL701

func Greet(name: string): string {
    return "hello " + name
}
```

The underline is on the quoted path, because the path is the only part of the line you can edit to
fix this.

```text
── [NL701] ERROR ───────────────────────────── Program.nl:1:8 ──

    1 | import "./formatting.nl"          // ERROR NL701
      |        ^^^^^^^^^^^^^^^^^

Cannot find import './formatting.nl'

I cannot find the file you're trying to import on line 1:

Hint: Make sure the file exists at the path './formatting.nl'.
The path should be relative to your project root.

Common issues:
  - Check for typos in the file path
  - Make sure the file extension is correct
  - Verify the file is in the expected directory
```

## Why is this an error?

An unresolved import is not a warning-level nuisance. Every name the file expected from it is now
missing, so continuing would bury one real mistake under a drift of [NL301](./NL301.md) and [NL201](./NL201.md) reports
about names that were never undefined. N# stops at the path.

## How to fix it

Point the import at a file that exists:

```n#
import "./formatter.nl"

func Greet(name: string): string {
    return Decorate("hello " + name)
}
```

## How the path is resolved

**The path is relative to the file that writes the import**, not to the project root. A file in
`sub/` reaching a sibling of the project root writes `../Helper.nl`; writing `./Helper.nl` from
there is NL701, even though `Helper.nl` sits at the root and is part of the same project.

**The `.nl` extension is optional.** `import "./Helper"` and `import "./Helper.nl"` resolve to the
same file. Pick one spelling and keep it — the two forms are distinct strings to every other tool
that reads your source.

A resolved path is only the beginning of the checks: an import that resolves can still be a cycle
([NL703](./NL703.md)), and two imports that both resolve can still collide
([NL702](./NL702.md)).

## Not to be confused with

NL701 is about **file** imports — the quoted-path form. A bare `import System.Text` names a
namespace, and a namespace that cannot be found is [NL704](./NL704.md) instead. The two forms look
similar and fail for entirely different reasons: one is a missing file on disk, the other is a
missing namespace in the referenced assemblies.
