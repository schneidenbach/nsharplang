# NL412: a called name resolves to nothing

N# resolved the name in front of the parenthesis and found nothing callable under it — no function
in this file, no imported function, no method on the enclosing type. Because nothing was called,
nothing about the arguments was checked either: NL412 is the first and only thing the compiler has
to say about this call site.

```n#
func Use(): int {
    return Compute(1)          // ERROR NL412
}
```

```text
── [NL412] ERROR ──────────────────────────── Program.nl:2:12 ──

    2 |     return Compute(1)          // ERROR NL412
      |            ^^^^^^^

Function 'Compute' not found

I cannot find a function named `Compute` on line 2:

Hint: Define `func Compute(...)` before calling it, or import the function if it lives elsewhere.
```

The last line is the useful one. N# scores every callable name in scope against the one you wrote
and prints the closest match as the suggestion, so a transposition like `Comptue` for `Compute`
answers itself.

## Why is this an error?

There is no later stage that could rescue this. N# resolves calls at compile time against names it
can see, and a name it cannot see has no signature, no return type, and no arity — every downstream
question about the call is unanswerable. Reporting one precise error beats reporting a cascade of
consequences.

## How to fix it

Define the function, or import whatever provides it:

```n#
func Compute(value: int): int {
    return value + 1
}

func Use(): int {
    return Compute(1)
}
```

## Which code you get for a name that is not there

NL412 is specifically about a **bare** callee — an identifier standing alone before `(`. Names that
fail in the neighbouring positions get their own codes, and the distinction is worth knowing because
the fixes are different:

| What you wrote | Code | What it means |
|---|---|---|
| `Compute(1)` — nothing named `Compute` | `NL412` | No callable by that name is in scope. |
| `greeter.Salute()` — no such member | [NL303](./NL303.md) | The receiver's type has no member with that name. |
| `Path.GetFullPath("a")` — no `import System.IO` | [NL002](./NL002.md) | The name exists; the file just never imported it. |
| `total` used as a value, undeclared | [NL301](./NL301.md) | An undefined variable, not an undefined function. |

The [NL002](./NL002.md) row is the one that surprises people. When the missing name is a **type** that N# can
locate in a referenced assembly, the linter claims the diagnostic first and tells you exactly which
`import` to add — you never reach NL412 at all.
