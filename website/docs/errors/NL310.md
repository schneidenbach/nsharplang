# NL310: this value must be a compile-time constant

Some positions in an N# program are not evaluated at run time at all — they are baked into metadata
by the compiler. An attribute argument is the common one. NL310 is what you get when you write an
expression there that only a running program could work out.

```n#
[System.Obsolete("use " + "Create")]          // ERROR NL310
func Make(): int {
    return 0
}
```

```text
── [NL310] ERROR ──────────────────────────── Program.nl:1:25 ──

    1 | [System.Obsolete("use " + "Create")]          // ERROR NL310
      |                         ^

Attribute arguments must be compile-time constants; operator '+' is not supported here

Suggestion: Use a literal, typeof(...), nameof(...), enum/static constant, or an array of those constants.
```

For a binary expression the caret is on the **operator**, not on the whole argument. That is the
token that has to go: both operands here are perfectly good constants, and the `+` between them is
the part the metadata cannot hold.

## Why is this an error?

Attribute arguments are written into the assembly's metadata tables at compile time and read back by
reflection, sometimes by a framework that never loads your code. There is no moment at which a call
or a concatenation could run. C# draws the same line for the same reason; N# just says so with a
message that names the offending piece rather than the whole attribute.

## How to fix it

Fold the value yourself, so what is left is a constant:

```n#
[System.Obsolete("use Create")]
func Make(): int {
    return 0
}
```

## What counts as a compile-time constant

The suggestion on the diagnostic lists the whole set, and it is short: a **literal**, `typeof(...)`,
`nameof(...)`, an **enum or static constant**, or an **array of those**. Two of them are worth
seeing, because they cover most of what people reach for concatenation to do:

```n#
[System.Obsolete(nameof(Make))]
func Make(): int {
    return 0
}
```

```n#
class Reasons {
    static readonly Use: string = "use Create"
}

[System.Obsolete(Reasons.Use)]
func Make(): int {
    return 0
}
```

Everything else is refused, and the message names the shape it saw rather than the whole argument:

- a **call** — `[System.Obsolete(Reason())]` reports `call expression is not supported here`;
- an **interpolated string**, even one with no holes in it — `$"use Create"` reports
  `interpolatedString expression is not supported here`, while the identical `"use Create"` is fine.
  The `$` turns a literal into an expression that builds a string at run time, and that is the whole
  difference.

## The other place N# asks for constants

Table-driven test rows take the same code, with their own sentence: `Table-driven test case values
must be compile-time constants`. The set there is narrower — the six literal kinds, a parenthesised
literal, and a negated numeric literal, because a table of negative numbers is ordinary. The reason
is the same one: the rows are read as data before anything runs.
