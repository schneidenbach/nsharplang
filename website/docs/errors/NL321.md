# NL321: an array allocation takes a length and nothing else

`new T[n]` is an array allocation, not a constructor call. It takes a length and nothing else — the
elements come back zero-initialized, and there is no constructor to pass arguments to. Adding a
constructor argument list or a C#-style `{ ... }` array initializer is NL321.

```n#
func Make(): int[] {
    return new int[4](7)          // ERROR NL321
}
```

For `new T[n](...)`, the underline is on `new`; for `new T[] { ... }`, it is on `{`.

```text
── [NL321] ERROR ──────────────────────────── Program.nl:2:12 ──

    2 |     return new int[4](7)          // ERROR NL321
      |            ^^^

Sized array allocation cannot also pass constructor arguments

Suggestion: Use 'new T[n]' for a zero-initialized array, or write the elements as a list — 'values := [1, 2, 3]'.
```

## Why is this an error?

`new int[4](7)` reads as though it might mean "four sevens", and it cannot: `new T[n]` maps directly
onto the CLR's array allocation, which has one input — the length. There is no per-element
initializer in that instruction and no constructor on `int[]` to receive `7`.

N# could have picked one of the two plausible readings and ignored the rest of the syntax. It reports
instead, because the two readings produce different arrays and nothing in the line says which one you
meant.

## How to fix it

If you wanted **`n` elements to fill in later**, drop the arguments — the array is already
zero-initialized:

```n#
func Zeros(n: int): int[] {
    return new int[n]
}
```

If you wanted **specific elements**, write them as a list:

```n#
func Values(): int[] {
    values := [1, 2, 3]
    return values
}
```

And if you wanted a fixed size with known contents, allocate and assign:

```n#
func Values(): int[] {
    values := new int[3]
    values[0] = 1
    values[1] = 2
    values[2] = 3
    return values
}
```

## What NL321 is not about

**Ordinary constructor calls are untouched.** `new Point(1, 2)` is a constructor call with
arguments, and this rule has nothing to say about it. NL321 fires when a sized array allocation also
has constructor arguments, or when an array allocation uses C#'s `{ ... }` initializer form.

**A wrong number of constructor arguments is [NL401](./NL401.md)**, and a wrong argument *type* is [NL202](./NL202.md).
NL321 is about combining a sized allocation with constructor arguments, or using C#'s array
initializer form; it does not report an argument count or type.

## `new T[] { ... }`

C# writes the elements of a new array in braces: `new byte[] { 1, 2 }`. N# has no such form; the
elements are a list, and the braces are refused on the `{` that opens them:

```n#
func Bytes(): byte[] {
    return new byte[] { 1, 2 }          // ERROR NL321
}
```

```text
N# has no array initializer syntax; write the elements as a list, '[1, 2]'

'new T[] { ... }' is C# syntax. Write the elements as a list — 'values := [1, 2]' — or use 'new T[n]' for a zero-initialized array of length n.
```

The sized spelling, `new byte[2] { 1, 2 }`, is refused the same way. The list literal is the fix:

```n#
func Bytes(): byte[] {
    values: byte[] = [1, 2]
    return values
}
```

Before this check the braces were accepted by the parser and the code generator stopped the build at
[NL103](./NL103.md) with `parse.function`, positioned at the start of the enclosing function rather than
at the braces. `tests/native/diagnostic-honesty` runs the suggested text through the shipped compiler on
every gate so the advice cannot drift.
