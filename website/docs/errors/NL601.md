# NL601: an operator overload that is not static

An operator overload is a rule about a pair of operands, not a message sent to one of them.
`a + b` has no receiver to dispatch on — both sides are arguments, and either may be the type
that defines the operator. So N# requires operator declarations to be `static`, and reports
NL601 when one is not.

```n#
class Money {
    Amount: int

    func operator +(left: Money, right: Money): Money {          // ERROR NL601
        return new Money { Amount: left.Amount + right.Amount }
    }
}
```

```text
── [NL601] ERROR ──────────────────────────── Program.nl:4:10 ──

    4 |     func operator +(left: Money, right: Money): Money {          // ERROR NL601
      |          ^^^^^^^^

Operator overloads must be declared 'static' — they don't belong to a specific instance

Suggestion: Operators must be public static and have correct parameter types
```

The caret covers the `operator` keyword rather than the symbol or the name. That is the token
the missing `static` belongs in front of.

## Why is this an error?

An instance operator would have to answer a question with no good answer: for `money + other`,
whose `+` runs? Operator resolution works from the *types* on both sides and looks for a static
method on either of them — an instance method is not in the set it searches. A non-`static`
operator therefore declares a method that nothing can reach through `+`; it compiles into a
member you could only ever call by name, which is not what you wrote it for.

## How to fix it

Add `static`. Both operands stay ordinary parameters:

```n#
class Money {
    Amount: int

    static func operator +(left: Money, right: Money): Money {
        return new Money { Amount: left.Amount + right.Amount }
    }
}
```

## The shape of an operator declaration

```text
static func operator <symbol>(<parameters>): <return type>
```

`static` is required, `operator` introduces the declaration, and the symbol follows it directly.
The parameters are the operands, left to right — there is no implicit `this` among them, which
is exactly why `static` is not optional.

## The symbols N# will accept after `operator`

Arithmetic `+ - * / %`, comparison `== != < <= > >=`, unary `! ~ ++ --`, bitwise
`& | ^ << >>`, and the two conversion operators `true` and `false`.

Anything else — `&&`, `||`, `??`, `=`, `[]` — is rejected by the parser, before NL601 is
reached, as an [NL103](./NL103.md) with the symbol quoted and the accepted set listed:

```text
Invalid operator symbol '&&' for operator overloading

This operator cannot be overloaded, or is not a valid operator symbol.

Hint: Only certain operators can be overloaded in operator declarations.

Suggestion: Arithmetic: +, -, *, /, %
```

So if you are looking for an NL601 about an unoverloadable symbol, it is an NL103 you want.

## Both faults report independently

`static` and the parameter count are checked separately, and a declaration that gets both wrong
is told about both. A non-`static` `%` with three parameters produces NL601 on the `operator`
keyword and [NL602](./NL602.md) on the `%`, in one compile. Fixing one does not hide the other.
