# NL305: not all code paths return a value

A function with a return type promises a value on every path out of it. NL305 is the compiler
finding a path with no `return` on it — usually the one you did not write, because the interesting
case was the one you did.

```n#
func Sign(n: int): string {          // ERROR NL305
    if n > 0 {
        return "positive"
    }
}
```

```text
── [NL305] ERROR ───────────────────────────── Program.nl:1:1 ──

    1 | func Sign(n: int): string {          // ERROR NL305
      | ^^^^^^^^^

Not all code paths return a value of type 'string'

This function is declared to return `string`, but not all code paths return a value:

Expected: `string`

Hint: Every code path through this function must end with a `return` statement that
provides a `string` value. If you don't need to return anything, change the
return type to `void`.

Suggestion: Add a `return` statement, or change the return type to `void`
```

The report lands on the **signature**, not on the closing brace. That is where the two available
fixes are: either the body must be completed to match the declared `string`, or the declaration
must stop promising one.

## Why is this an error?

`Sign` claims to hand back a `string`. On the `n <= 0` path it hands back nothing, and every caller
that wrote `Sign(x).Length` would be reading a value the function never produced. N# does not have a
"default value" escape hatch for this — a `string` that is sometimes absent is a `string?`, and that
is a different signature with different obligations at every call site.

## How to fix it

Return on the path that falls through:

```n#
func Sign(n: int): string {
    if n > 0 {
        return "positive"
    }

    return "not positive"
}
```

## What counts as returning

The check is about *leaving with a value*, not about the literal keyword, so several shapes satisfy
it:

- **Every branch returns.** An `if` with an `else` where both sides return is itself a returning
  statement, so a body that ends in one is complete. The check folds nested statements the same way:
  the only question it ever asks is whether control can reach the end of the body.
- **A `throw` at the end.** Leaving by exception is leaving:

```n#
import System

func Sign(n: int): string {
    if n > 0 {
        return "positive"
    }

    throw new InvalidOperationException("no")
}
```

- **A `void` function.** Nothing is promised, so nothing is checked. If a function genuinely has
  nothing to hand back, dropping the return type is the fix rather than returning a placeholder.

## The relationship with NL312

These two codes are opposite ends of the same analysis. NL305 says control can reach the end of the
body without returning; [NL312](./NL312.md) says control cannot reach a statement at all because
every path already returned. A body that satisfies one usually cannot trip the other.
