# NL407: a params parameter is not last

A `params` parameter absorbs every remaining argument at a call site, so there can be nothing after
it to absorb. N# checks this on the **declaration**, before any call is bound, and underlines the
misplaced parameter rather than the ones it displaced.

```n#
func Log(params items: string[], suffix: string): string {          // ERROR NL407
    return items.Length.ToString() + suffix
}
```

```text
── [NL407] ERROR ──────────────────────────── Program.nl:1:17 ──

    1 | func Log(params items: string[], suffix: string): string {          // ERROR NL407
      |                 ^^^^^

A 'params' parameter must come last in the parameter list — move it to the end
```

The check runs over the whole list, so a declaration with two `params` parameters reports twice —
each one that is not last is its own mistake.

## Why is this an error?

Argument binding for a `params` tail is positional and greedy: everything from that position on
becomes the array. A parameter declared after it could never receive an argument, because there is
no call shape that would reach it — the caller has no syntax for "stop the params here". The
declaration is unusable rather than merely unusual, so N# rejects it where it is written.

## How to fix it

Move it to the end. The fixed parameters come first, in the order callers supply them:

```n#
func Log(suffix: string, params items: string[]): string {
    return items.Length.ToString() + suffix
}
```

## One parameter, two possible reports

The position rule and the type rule are independent, and a misplaced `params` parameter with a bad
type reports **both** — NL407 and [NL405](./NL405.md) — at the same span:

```n#
func Log(params level: int, suffix: string): string {          // ERROR NL407 and NL405
    return level.ToString() + suffix
}
```

That is deliberate. Silencing the type rule because the position rule already fired would tell you
about the second fault only on your next build.

## Where the rule applies

Every declaration in N# that has a parameter list runs this check: a top-level function, a local
function, a constructor, an indexer, a `test` declaration, and the primary constructor of a class,
struct or record. There is no declaration form where a trailing `params` is optional.

A `params` parameter never carries a default, so the optional-parameter rules skip it entirely: it
is neither optional itself nor a required parameter that could trip [NL409](./NL409.md).
