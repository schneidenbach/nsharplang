# NL409: a required parameter after an optional one

Once a parameter has a default, every parameter after it must have one too. N# checks this left to
right on the declaration and reports against the first required parameter that appears too late.

```n#
func Make(width: int = 1, height: int): int {          // ERROR NL409
    return width * height
}
```

```text
── [NL409] ERROR ──────────────────────────── Program.nl:1:27 ──

    1 | func Make(width: int = 1, height: int): int {          // ERROR NL409
      |                           ^^^^^^

Required parameter 'height' can't come after optional parameters — move it before the optional ones, or give it a default value too
```

The underline is on `height` — the parameter that cannot be reached — not on `width`, the one that
introduced the default. Both spellings in the message are real fixes; the compiler does not choose
between them for you.

## Why is this an error?

Arguments bind by position. A caller writing `Make(3)` fills the first parameter, so a required
parameter sitting behind a defaulted one can only be reached by a caller who also supplies the
default — which makes the default meaningless and the "required" parameter effectively optional.
Rather than let a signature say two contradictory things, N# rejects the ordering.

## How to fix it

Move the required parameter in front of the optional ones:

```n#
func Make(height: int, width: int = 1): int {
    return width * height
}
```

Giving `height` a default of its own is the other legal answer, and it changes the API rather than
just its order — every caller may then omit it.

## What the rule skips

Two kinds of parameter are stepped over before the question is asked, so neither can trip the rule
and neither counts as optional for the parameters that follow:

- a `this` receiver, which is always supplied by the call syntax;
- a `params` tail, which never carries a default.

The `params` case is the one worth remembering: `func Log(width: int = 1, params items: string[])`
is not NL409, because the `params` parameter is neither optional nor required in the sense this rule
measures. The current backend does not lower that combination yet and reports
[NL103](./NL103.md) for it instead — a separate limitation, not this rule.
