# NL204: no conversion exists between these types

A cast asserts that a value **already is** the type you name. It does not convert one thing into
another. When no conversion of any kind exists between the two types, the assertion can never
hold and the cast is a mistake rather than an instruction.

```n#
func Label(count: int): string {
    return (string)count         // ERROR NL204
}
```

```text
── [NL204] ERROR ──────────────────────────── Program.nl:2:12 ──

    2 |     return (string)count         // ERROR NL204
      |            ^^^^^^^

'int' cannot be cast to 'string' — no conversion exists between them

Suggestion: A cast only reinterprets a value that already IS a 'string'; it never converts one. If you meant to convert, call a conversion — `x.ToString()`, `Convert.ToString(x)`, `Convert.ToInt32(x)` or `Int32.Parse(text)`.
```

## How to fix it

Call a conversion. Which one depends on the direction:

```n#
func Label(count: int): string {
    return count.ToString()
}
```

`Int32.Parse(text)` goes the other way, and `Convert.ToString(x)` / `Convert.ToInt32(x)` handle
the general case.

## The `as` spelling gets its own sentence

`as` is the same assertion with a `null` instead of a failure, and it is subject to the same
rule — a conversion that does not exist does not start existing because you asked politely:

```text
'int' cannot be converted to 'string' with `as` — no conversion exists between them
```

## What IS a conversion

The rule is deliberately generous, because the cost of a false accusation is much higher than
the cost of a missed one. All of these are conversions and none of them is reported:

- **The numeric domain, at every width and in both directions.** `(int)3.5`, `(byte)n`,
  `(char)65`, `(long)someDecimal` — that is exactly what an explicit numeric conversion is.
  `bool` is not in this domain, and neither is `string`.
- **Enums**, to and from numbers and to other enums.
- **Boxing and unboxing** through `object`, in either direction.
- **Any upcast or downcast** along a real inheritance chain, and anything involving an interface
  — a type you have not seen may implement it.
- **A user-declared conversion operator** on either type.
- **Anything the compiler could not fully model** — an unresolved name, a type from another
  assembly, an open generic. A name nobody resolved is [NL201](./NL201.md)'s report, never this
  one.

## A known gap

Two **unrelated unsealed classes** are not reported today. The judgement is shared with the
pattern-reachability rules, which admit the pair because an unseen subclass could in principle be
the link — a conservatism that is right for `is` and too generous for a cast. The shape reaches
the backend and is refused there instead.
