# NL405: an illegal params parameter type

A `params` parameter is the array a call site's trailing arguments are collected into, so its
declared type has to be something those arguments can be collected into. N# checks the declared type
where it is written, not at the first call.

```n#
func Log(params level: int): string {          // ERROR NL405
    return level.ToString()
}
```

```text
── [NL405] ERROR ──────────────────────────── Program.nl:1:17 ──

    1 | func Log(params level: int): string {          // ERROR NL405
      |                 ^^^^^

A 'params' parameter must be an array or collection type — 'int' is not a valid params type
```

The span covers the parameter's name, and the type named in the message is the one you declared —
`int` here, not `int[]`.

## Why is this an error?

`params` is a calling convention, not a hint. At every call site the compiler builds a collection
from the trailing arguments and passes that single value, and it needs a type it can build. A scalar
`int` has no such construction, so the declaration describes a convention the compiler cannot
implement.

## How to fix it

Declare the element type as an array:

```n#
func Log(params levels: int[]): string {
    return levels.Length.ToString()
}
```

## Which types a `params` parameter may have

The accepted set is closed and checked **by name**, not by assignability. It is:

- any array type — `int[]`, `string[]`, `Box[][]`;
- `Span<T>` and `ReadOnlySpan<T>`;
- `IEnumerable<T>`, `IReadOnlyCollection<T>`, `IReadOnlyList<T>`, `ICollection<T>`, `IList<T>`;
- `List<T>`, `HashSet<T>`, `Queue<T>`, `Stack<T>`;
- `ArraySegment<T>`, `Memory<T>`, `ReadOnlyMemory<T>`.

So this is accepted, and is a real alternative when the body wants a list rather than an array:

```n#
import System.Collections.Generic

func Log(params items: List<string>): int {
    return items.Count
}
```

Two consequences of the check being by name are worth knowing. A scalar type and `string` are
refused because neither is an array nor one of those generics. And a collection type of *your own*
is refused even when it implements `IEnumerable<T>` — the list above is the whole rule, and a
custom collection has to be taken as an ordinary (non-`params`) parameter.

## Two rules, one parameter

The type rule and the position rule are separate checks over the same list, and one does not silence
the other. A `params` parameter that is both misplaced and badly typed reports NL405 **and**
[NL407](./NL407.md) at the same span, so a single build shows you both faults.
