# NL001: a local variable is never read

A local you declare and then never mention again is an error in N#, not a warning. It is almost
always a half-finished edit — the value was computed to feed something, and the line that read it
was renamed, moved, or never written. When the local really is deliberate, the `_` prefix is a
first-class opt-out, so the rule never forces you to delete something you meant to keep.

```n#
func Total(prices: int[]): int {
    sum := 0
    count := prices.Length          // ERROR NL001
    for price in prices {
        sum = sum + price
    }

    return sum
}
```

```text
── [NL001] ERROR ───────────────────────────── Program.nl:3:5 ──

    3 |     count := prices.Length          // ERROR NL001
      |     ^^^^^

Variable 'count' is declared but never read

Suggestion: If this is intentional, prefix it with '_' to indicate it's unused: '_count'
```

The suggestion is the entire decision: `_count` if the declaration should stay, deletion if it
should not.

## Why is this an error?

N# is near-zero-warnings on purpose. A diagnostic nobody has to act on is a diagnostic everybody
filters out, and once a project has ten of them it has stopped reading any of them. So the hygiene
rules that catch real mistakes block the build, and each one ships with an opt-out that costs a
single keystroke. `_count` is not a workaround — it is how you say "I know, and I meant it", and the
compiler will not ask again.

The mistake this catches is rarely "I wrote a variable I did not need". It is "I read the wrong
one". A dead local next to a live one of a similar name is exactly the shape a typo makes.

## How to fix it

Delete the declaration, or feed it into the code that was supposed to use it:

```n#
func Total(prices: int[]): int {
    sum := 0
    for price in prices {
        sum = sum + price
    }

    return sum
}
```

## What counts as a use

- **A read, anywhere the local is in scope** — including inside an interpolated string hole.
  `return $"count={count}"` is a use of `count`.
- **A write is not a read.** `total := 0` followed by `total = 5` and nothing else is NL001, on the
  declaration — a value nothing ever reads back is a half-finished edit whether or not the name
  appears again. Three shapes that look like writes are reads and do not count against you:
  `total += 1` (and `-=`, `*=`, `/=`, `??=`) reads `total` to compute the new value; `values[0] = 1`
  reads `values` to find the element; and `box.Field = 1` reads `box` to find the member.
- **`_` and every `_`-prefixed name are exempt**, and that is the documented opt-out: `_scratch`,
  `_tmp` and the bare discard `_` are all silent.
- **A `catch` clause's exception variable is never reported.** `catch (error: FormatException)`
  whose body never mentions `error` is fine — binding the exception is how you name the clause, not
  how you use a value.
- **Parameters are not locals here.** An unused parameter is [NL012](./NL012.md), which has its own
  message and its own `_` opt-out.

To silence one site without renaming it, put `// nlc:ignore NL001` on the line before the
declaration, or trailing the declaration itself. Both forms work.
