# NL341: a direct call to the runtime's finalizer slot

`Finalize` is the slot the garbage collector calls when it is about to reclaim an object. It runs on
the finalizer thread, at a moment no source line chooses, and it may run *concurrently* with code
still holding the object. Calling it from source would run the cleanup a second time — once now, and
again when the collector gets there.

N# refuses the call, exactly as C# does (CS0245).

```n#
import System

class Handle: Exception {
    public func Close(): int {
        this.Finalize()                  // ERROR NL341
        return 1
    }
}
```

```text
── [NL341] ERROR ────────────────────────────────── Program.nl:5:14 ──

    5 |         this.Finalize()                  // ERROR NL341
      |              ^^^^^^^^

`Finalize` is the runtime's finalizer and cannot be called from source — the garbage collector calls
it, on its own schedule

Suggestion: Release resources deterministically instead: implement `IDisposable` and call `Dispose()`,
or wrap the value in a `using` statement.
```

## How to fix it

**Release deterministically with `IDisposable`.** This is what the call was almost certainly reaching
for: a cleanup that happens *when you say so*, not when the collector decides.

```n#
import System

class Handle: IDisposable {
    closed: bool

    public func Dispose(): void {
        if closed {
            return
        }

        closed = true
    }
}

func Use(): void {
    using h := new Handle()
    // `h.Dispose()` runs at the end of the scope, deterministically.
}
```

**Suppress the finalizer after disposing**, if the type has one. `GC.SuppressFinalize` *is* callable
from source — it tells the collector the cleanup already happened:

```n#
import System

class Handle: IDisposable {
    public func Dispose(): void {
        GC.SuppressFinalize(this)
    }
}
```

## What is still allowed

The rule is about the **override chain**, not about the name. Only the slot that overrides
`System.Object.Finalize` is refused: a parameterless method that merely happens to be named
`Finalize` on an unrelated type is an ordinary method and calls to it are fine.

`object`'s other protected member, `MemberwiseClone`, is callable from inside the type that inherits
it — it has no schedule of its own:

```n#
class Point {
    X: int

    public func Copy(): object? {
        return this.MemberwiseClone()
    }
}
```
