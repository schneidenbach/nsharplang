# NL602: an operator overload with the wrong number of operands

An operator's parameters are its operands, and how many operands an operator takes is fixed by
the language, not by the declaration. `*` is binary and always takes two; `!` is unary and
always takes one. NL602 is the report when the parameter list does not match the symbol.

```n#
class Money {
    Amount: int

    static func operator *(factor: int): Money {          // ERROR NL602
        return new Money { Amount: factor }
    }
}
```

```text
── [NL602] ERROR ──────────────────────────── Program.nl:4:26 ──

    4 |     static func operator *(factor: int): Money {          // ERROR NL602
      |                          ^

Operator '*' requires exactly 2 parameter(s), but you declared 1
```

The caret is on the symbol, because the symbol is what decides the count. The message gives the
required number and yours, and nothing else — there is only one thing to change.

## Why is this an error?

`money * 2` supplies exactly two values. A one-parameter `*` has nowhere to put the left
operand, and a three-parameter one has a parameter no call site can ever fill. Unlike a normal
function, an operator has no way to be called with a different number of arguments, so a
mismatched arity is not an overload — it is a method that can never run.

## How to fix it

Give the operator one parameter per operand, left to right. The left operand comes first:

```n#
class Money {
    Amount: int

    static func operator *(left: Money, factor: int): Money {
        return new Money { Amount: left.Amount * factor }
    }
}
```

The two operands do not have to be the same type. `Money * int` is a perfectly good operator;
what matters is that there are two of them.

## The required count for every symbol

| Operands | Symbols |
|---|---|
| 1 | `!` `~` `++` `--` `true` `false` |
| 2 | `*` `/` `%` `==` `!=` `<` `<=` `>` `>=` `&` <code>&#124;</code> `^` `<<` `>>` |
| 1 or 2 | `+` `-` |

`+` and `-` are the only two that may be either. Both spellings are accepted from the same type,
and a unary `-` on its own compiles clean:

```n#
class Money {
    Amount: int

    static func operator -(a: Money): Money {
        return a
    }
}
```

Because they have two legal counts, they get their own wording — the count you wrote is
compared against a range rather than against a number:

```text
Operator '+' can be unary (1 parameter) or binary (2 parameters), but you declared 3
```

## Two mistakes that look like NL602 and are not

**A symbol N# does not overload.** `&&`, `||`, `??`, `=` and `[]` are rejected by the parser
before any arity is counted, as an [NL103](./NL103.md) reading *Invalid operator symbol*. There
is deliberately no arity complaint on top of it: the number of operands for an operator the
language does not have is not a question worth answering.

**A missing `static`.** That is [NL601](./NL601.md), and it is checked independently — a
declaration with both faults reports both, NL601 on the `operator` keyword and NL602 on the
symbol.

## The parameters still have to be read

An operator body that ignores an operand is a lint error like any other function's. A binary
`+` that never touches `right` reports [NL012](./NL012.md) — *Parameter 'right' in 'operator +' is never
read* — alongside anything else wrong with the declaration. Fixing the arity and leaving the new
parameter unused trades one diagnostic for another.
