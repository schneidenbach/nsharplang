# NL704: namespace not found

A bare `import` names a namespace, and that namespace has to exist in something the project
references. NL704 is what you get when it does not: the name was searched for across the referenced
assemblies and the built-in namespace table, and nothing answered to it.

```n#
import System.Collectons.Generic          // ERROR NL704

func Greet(name: string): string {
    return "hello " + name
}
```

The underline covers the whole dotted name, because any segment of it could be the wrong one.

```text
── [NL704] ERROR ───────────────────────────── Program.nl:1:8 ──

    1 | import System.Collectons.Generic          // ERROR NL704
      |        ^^^^^^^^^^^^^^^^^^^^^^^^^

I can't find namespace 'System.Collectons.Generic' — check the spelling and make sure the assembly is referenced

Suggestion: Check the namespace spelling and project references.
```

## Why is this an error?

An import that names nothing brings in nothing, and every type the file expected from it is now
unresolvable. Reporting the import is the difference between one diagnostic you can act on and a
page of [NL201](./NL201.md) reports about types that are spelled correctly.

## How to fix it

Fix the spelling, or add the reference the namespace lives in:

```n#
import System.Collections.Generic

func Names(): List<string> {
    return new List<string>()
}
```

## The two things NL704 actually means

**The namespace does not exist anywhere N# looked.** This is the typo case — `System.Collectons`
above — and also the case of a namespace from a package the project has not referenced. The message
covers both deliberately: "check the spelling and make sure the assembly is referenced" is not
hedging, it is the honest set of two possibilities the compiler cannot distinguish.

A real namespace whose assembly is simply not on the reference list reads exactly the same way:

```n#
import System.Data          // ERROR NL704: I can't find namespace 'System.Data'
```

That one is spelled correctly. It is reported because `System.Data.dll` is not among the assemblies
this project loads — add the reference and the same line compiles.

**The name resolves, but to a type.** Importing `System.String` is not importing a namespace, and
N# says so in its own sentence rather than pretending the name was not found:

```n#
import System.String        // ERROR NL704: 'System.String' is a type, not a namespace
```

The fix there is to import the enclosing namespace (`import System`) and use the type by name. N#
has no "import a single type" form — a namespace import brings the whole namespace, and the file
import (`import "./lib/text.nl"`) is the mechanism for reaching into one specific place.

## Not to be confused with

A quoted path (`import "./lib/text.nl"`) is a **file** import and fails as
[NL701](./NL701.md), not NL704. If your import has quotes around it, NL704 is not the code you
will see.
