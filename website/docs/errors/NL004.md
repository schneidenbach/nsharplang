# NL004: an async function that never awaits

A function marked `async` whose body never awaits is an error. The modifier builds a task-returning
state machine and changes how exceptions are delivered, but a body with no suspension point has no
asynchronous work to coordinate. The signature asks every caller to await a task for a body that
could be an ordinary function.

```n#
import System.Threading.Tasks

async func LoadName(): Task<string> {          // ERROR NL004
    return "ada"
}
```

```text
── [NL004] ERROR ──────────────────────────── Program.nl:3:12 ──

    3 | async func LoadName(): Task<string> {          // ERROR NL004
      |            ^^^^^^^^

Function 'LoadName' is marked 'async' but never uses 'await'

Suggestion: Either add an 'await' expression inside 'LoadName', or remove the 'async' modifier if this function doesn't need to be asynchronous
```

The span is the function's name, and the message names it again in the suggestion, because the fix
is a choice about this declaration rather than about any one line inside it.

## Why is this an error?

`async` wraps the body in a state machine and changes its contract: the call returns a task, and a
thrown exception becomes a fault on that task. A body without `await` cannot suspend, so the task
adds an asynchronous boundary without doing asynchronous work. NL004 catches an accidental missing
`await` and makes the declaration match its actual behavior.

The mistake is usually directional. Either the `await` was removed and the modifier was left, in
which case the function should be synchronous; or the asynchronous call was never written, in which
case the body is not finished. Both are worth stopping the build for, and the diagnostic offers
both.

## How to fix it

Await the thing the function was written to await:

```n#
import System.Threading.Tasks

async func LoadName(): Task<string> {
    await Task.Delay(1)
    return "ada"
}
```

Or drop `async` and let the function be what it is:

```n#
func LoadName(): string {
    return "ada"
}
```

The second form is not a smaller version of the first. Dropping `async` changes the return type and
therefore the call sites, which is the point: a function that does not suspend should not ask its
callers to await it.

## What counts as an await

Any `await` anywhere in the body, at any depth. An `await` that only runs on one branch still
counts — this function is accepted:

```n#
import System.Threading.Tasks

async func LoadName(retry: bool): Task<string> {
    if retry {
        await Task.Delay(1)
    }

    return "ada"
}
```

The rule is about the declaration, not about whether the await is reachable, so it never asks
whether `retry` can be true. One `await` in the body is enough, and nothing else silences it except
`// nlc:ignore NL004` on the line above the declaration.
