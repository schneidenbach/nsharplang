# NL904: `ref` used for an `in` parameter

Since C# 12, a `ref` argument may be passed to an `in` parameter. The parameter still receives a
read-only reference, so the call is valid; NL904 advises spelling the argument `in` to match the
callee's contract.

```n#
func Read(in value: int): int {
    return value
}

func main() {
    value := 41
    print Read(ref value) // WARNING NL904
}
```

```text
warning NL904: The 'ref' modifier for argument 1 corresponding to 'in' parameter is equivalent to 'in'. Consider using 'in' instead.
```

## How to fix it

Use `in` at the call site:

```n#
print Read(in value)
```

You may also omit the modifier because the parameter declaration already says the call uses a
read-only reference:

```n#
print Read(value)
```

`in` is not interchangeable with a by-value parameter. Writing `in` for one, or using `ref` or
`out` where the parameter requires a by-value argument, remains invalid.

## Overload resolution

The compiler selects overloads before reporting NL904. A `ref` argument can make an `in` overload
applicable, and its ref-kind is treated like `ref` when comparing applicable overloads. With no
argument modifier, an otherwise identical by-value overload remains preferred over `in`.
