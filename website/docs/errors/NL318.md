# NL318: off applied to something that is not a subscription

`on` subscribes to a .NET event and gives you back a **subscription**; `off` takes that subscription
and detaches it. NL318 is what you get when either keyword is handed the wrong thing — an `off` whose
operand did not come from an `on`, or an `on` pointed at something that is not an event.

```n#
import System

func Detach(handler: Action) {
    off handler          // ERROR NL318
}
```

The underline is on the operand, not on the keyword: `off` is right, the value it was given is not.

```text
── [NL318] ERROR ───────────────────────────── Program.nl:4:9 ──

    4 |     off handler          // ERROR NL318
      |         ^^^^^^^

`off` expects a subscription returned by `on`

Suggestion: Capture the subscription first (`sub := on <object>.<Event> handler`), then detach it with `off sub`.
```

## Why is this an error?

`off` does not search for a matching handler — that is the C# `-=` design, and it is exactly what N#
avoids. `on` returns a handle that identifies one subscription, and `off` uses the handle. A delegate
is not that handle: two subscriptions made with the same handler are two different subscriptions, and
there would be no way for `off handler` to say which one you meant.

Given a value that is not a handle, N# has nothing to detach and no way to guess. It reports rather
than picking one.

## How to fix it

Keep the value `on` gave you, and pass that:

```n#
import System

func Watch() {
    sub := on Console.CancelKeyPress (sender, args) => { }
    off sub
}
```

The subscription is an ordinary value. Store it in a field when the subscription outlives the
function that made it, and detach later from wherever you kept it.

## The other half: `on` pointed at a non-event

The same code covers the mirror-image mistake. `on` requires a .NET event, and a plain field or
property is not one:

```n#
class Signal {
    Name: string
}

func Watch(s: Signal) {
    on s.Name (sender, args) => { }    // ERROR NL318: `on` can only subscribe to a .NET event
}
```

The hint there points at the alternative that actually applies to plain delegates: to combine
`Func`/`Action` values, use `+=` on the field. `on` and `off` are for events specifically.

## When it is NL317 instead

Writing the **event itself** after `off` is [NL317](./NL317.md), not NL318:

```n#
off Console.CancelKeyPress       // NL317: 'CancelKeyPress' is a .NET event and can only be
                                 //        used with `on`/`off`
```

The distinction is which rule you broke. Naming an event where a value is expected is an event
misuse, and NL317 owns every one of those. NL318 is for operands that are legal values but the
wrong kind of value.
