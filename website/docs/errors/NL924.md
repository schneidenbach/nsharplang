# NL924: internal compiler error

An unexpected exception escaped the compiler's command handler. **This is a bug in N#, not in your
code.** The process exits with status **2**, distinct from success (`0`) and ordinary diagnostics or
command failures (`1`).

An internal invariant failure cannot be reproduced by a supported source program. This example is
real output from the command boundary, exercised with a synthetic exception by
`tests/native/cli-command-contracts/InternalErrorBoundary.tests.nl`:

```text title="NL924 boundary output"
error NL924: Internal compiler error.
This is a bug in N#, not in your code.
AnalyzerScopeStack requires a non-empty scope stack before Peek.
Exception: System.InvalidOperationException
Report this failure: https://schneidenbach.github.io/nsharplang/docs/errors/NL924
```

The invariant sentence and exception type vary with the failure. A source file may prefix the
first line when known; no line, column, or span is guessed. The boundary does not print a stack trace.

## Report the failure

[Open an N# issue](https://github.com/schneidenbach/nsharplang/issues/new) and include the complete
NL924 output, `nlc --version`, the command you ran, your operating system and .NET version, and the
smallest source/project configuration that still triggers the failure. Remove secrets before
sharing a project. You do not need to change correct source code to satisfy an internal invariant.

`nlc run` forwards the launched program's exit status, including `2`. In that case the number alone
does not identify an internal compiler failure: NL924 on stderr supplies that distinction.

## JSON requests

An exception escaping a JSON command also prints this plain diagnostic to **stderr**, exits `2`,
and leaves stdout untouched. Any output already written may be incomplete: check the exit status
before parsing a successful command response. No new JSON schema or error envelope is implied.
Existing command-local error handlers retain their documented output and exit status.
