# NL501: a match that does not cover every case

When the scrutinee's type has a closed set of alternatives, a `match` has to account for all of
them. N# names the ones you left out rather than telling you the match is incomplete and letting you
find the gap.

```n#
enum Color {
    Red = 0,
    Green = 1,
    Blue = 2
}

func Name(color: Color): string {
    return match color {          // ERROR NL501
        Color.Red => "red",
        Color.Green => "green"
    }
}
```

```text
── [NL501] ERROR ──────────────────────────── Program.nl:8:12 ──

    8 |     return match color {          // ERROR NL501
      |            ^^^^^

Pattern matching is not exhaustive

This `match` expression does not cover all possibilities on line 8:

Hint: You need to handle these cases:

    Blue

Pattern matching in N# must be exhaustive, meaning every possible value
must be handled. You can either add the missing cases, or use a wildcard '_'
pattern to catch everything else:

    _ => handleOtherCases()

Why? This helps prevent runtime errors. The compiler checks that you've thought
about all possibilities!
```

The diagnostic underlines the `match` keyword, because the omission belongs to the expression as a
whole rather than to any one arm. The missing names are listed in declaration order.

## Why is this an error?

A `match` that falls off the end has to produce *something*. Every language that allows it picks a
silent answer — a null, a zero, an exception at run time — and every one of those turns "I forgot the
`Blue` case" into a bug found by a user rather than by a compiler. N# already knows the full set of
alternatives at compile time, so it says so.

Exhaustiveness is also what IL lowering reads: a match proven total emits no fall-through arm at all.

## How to fix it

Handle the missing case:

```n#
enum Color {
    Red = 0,
    Green = 1,
    Blue = 2
}

func Name(color: Color): string {
    return match color {
        Color.Red => "red",
        Color.Green => "green",
        Color.Blue => "blue"
    }
}
```

Or add a `_ => ...` wildcard arm, if the remaining cases really do share an answer.

The two fixes are not interchangeable in the long run. A wildcard over an enum you own means that adding a
member later compiles silently; spelling out the cases means the compiler brings you back here.

## Which types are checked

Only four kinds of scrutinee have a set N# can enumerate, and each is checked differently:

| Scrutinee | How coverage is proved |
|---|---|
| An anonymous union (`string \| int`) | Arm by arm, by **assignability** — one `object` pattern can cover every arm at once. |
| A declared `union`, including a closed generic one | Case by case, by **name**. |
| An `enum` | Member by member, by name **and** by literal value. |
| A nullable `T?` | The two-element set `{null, present}`. |

Everything else — `bool`, `int`, `string`, a class, an interface — has no closed set to enumerate,
so N# never reports NL501 for it. A `match` on a `bool` with only a `true` arm compiles; the
compiler simply records the match as non-exhaustive and lowering supplies a fall-through. If you want
a total answer there, write the `_` arm yourself.

## Guarded arms never cover anything

Every one of the four walks skips an arm with a `when` clause before it looks at the pattern, because
a guard may be false at run time:

```n#
union Shape {
    Circle { radius: double }
    Square { side: double }
}

func Describe(shape: Shape): string {
    return match shape {          // ERROR NL501: missing Circle
        Shape.Circle { radius: r } when r > 0.0 => "circle",
        Shape.Square { side: _ } => "square"
    }
}
```

`Circle` is reported missing even though an arm names it. A guarded arm is a *filter*, not a case,
and the fix is an unguarded arm for the same case after it.

## Partially covered union cases

A union arm that constrains a property covers only the values satisfying the constraint, so
`Result.Success { value: 0 }` does not cover `Success`. N# reports the case as partially covered, and
when the constraint ranges over a **nested** union it computes whether the nested arms together are
total — naming the exact missing nested arm when they are not, as
`Error (missing nested arm: Result.Error { kind: Kind.Parse })`.

## Nullable scrutinees read differently

For a `T?`, N# looks for one arm covering `null` and one covering the present value. A `null`
literal pattern covers the first; a type test, object, positional or list pattern, or an undotted
binding covers the second. Only `_` covers both:

```n#
func Describe(text: string?): string {
    return match text {          // ERROR NL501: doesn't cover null
        value => value
    }
}
```
