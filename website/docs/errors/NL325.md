# NL325: declared interface is not implemented

A type that names an interface in its declaration promises callers every member of that
interface. A class, struct or record that leaves one unimplemented is a type that cannot
satisfy the calls its own declaration invites.

```n#
interface Greeter {
    func Greet(): string
    func Farewell(): string
    Name: string
}

class English : Greeter {       // ERROR NL325
    func Greet(): string {
        return "hello"
    }
}
```

```text
`English` declares an interface but does not implement 2 of its members: `Farewell`, `Name`:

7| class English : Greeter {
         ^^^^^^^

Hint: Implement all 2 in `English`, inherit them from a base class, or drop the interface
from the declaration.
```

The report is **one diagnostic naming every missing member**, not one per member — the same
rule [NL324](./NL324.md) follows, and for the same reason.

## Why is this an error?

An interface is a contract with callers, not a label. Code that holds a `Greeter` may call
`Farewell()` on it; if `English` never wrote one, that call has nothing to reach. The CLR
will not load such a type, so before this check existed the mistake surfaced at run time
rather than at `nlc check`.

## What counts as an implementation

A member of the **same name**. N# has only *implicit* implementation — there is no explicit
interface implementation syntax — so a member satisfies an interface simply by being there:

```n#
class English : Greeter {
    func Greet(): string => "hello"
    func Farewell(): string => "goodbye"
    Name: string => "English"
}
```

**Functions and value members are matched separately**, but fields and properties count as
one kind. An interface writes its value members bare (`Name: string`) and an implementer may
answer with either spelling — a bare member or one with an accessor — because N# does not
make the caller choose.

**A default implementation requires nothing.** An interface member written *with a body* is
inherited by every implementer:

```n#
interface IShape {
    func GetArea(): double

    func Describe(): string {        // has a body — a default implementation
        return $"Area: {GetArea()}"
    }
}

class Circle : IShape {              // fine — only `GetArea` is a slot
    func GetArea(): double {
        return 3.14
    }
}
```

**A base class can satisfy the interface for you.** The check counts everything the type
inherits, so a member supplied anywhere up the base-class chain closes the slot:

```n#
class BaseImpl {
    func Greet(): string => "hello"
}

class English : BaseImpl, Greeter {  // fine — `BaseImpl` supplies `Greet`
}
```

## Interfaces from other assemblies

The rule covers CLR interfaces through the same walk, including generic ones closed over the
implementing type:

```n#
class Resource : IDisposable {       // ERROR NL325: does not implement its member 'Dispose'
}

class Version2 : IComparable<Version2> {   // ERROR NL325: ... its member 'CompareTo'
}
```

An interface that **extends another** brings the inherited members with it —
`IEnumerable<T>` requires `GetEnumerator` once, not twice.

## When N# stays quiet

- a type that declares **no interface**;
- an **abstract** class, which may leave the obligation to its subclasses;
- an interface declaration itself;
- an entry in the base list that **does not resolve**, or resolves to a class rather than an
  interface — the first is `NL201`'s business and the second is [NL324](./NL324.md)'s;
- any link in the base-class or base-interface chain whose shape the compiler cannot open. A
  missing-member list computed from half a chain is not a missing-member list, so the whole
  report is abandoned rather than partially issued.

Matching is by name, so **overloads are not distinguished**. Where an external type declares
several members of one name and only some are abstract, the name counts as supplied. That is
the under-reporting direction, chosen deliberately: the worst failure for a rule like this is
the correct program it rejects.
