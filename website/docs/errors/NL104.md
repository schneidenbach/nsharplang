# NL104: the file ended in the middle of something

The parser was waiting for a specific piece of your program and reached the end of the file instead.
This is [NL102](./NL102.md)'s situation with nothing left to read.

```n#
namespace          // ERROR NL104
```

```text
── [NL104] ERROR ───────────────────────────── Program.nl:1:1 ──

    1 | namespace          // ERROR NL104
      | ^^^^^^^^^

Expected identifier, but reached the end of the file

I was expecting an identifier here, but the file ended first.

Hint: Finish this construct before the end of the file.
```

## Why is this an error?

There is nothing to point at except the end of the file, so N# points at the construct that was
still open — here the `namespace` keyword — rather than at the last character. "Expected a
namespace name" is actionable; "unexpected end of file" alone is not.

## How to fix it

Finish the construct:

```n#
namespace Weather

func Greet(): string {
    return "hi"
}
```

## The usual causes

- a file that was truncated by an editor crash, a partial paste, or a bad merge;
- a declaration keyword typed and then left — `class`, `func`, `enum`, `interface`, `import`;
- a construct whose closing delimiter is missing at the *very end* of the file. When the compiler
  can tell which delimiter it was, it reports [NL106](./NL106.md), [NL107](./NL107.md) or
  [NL108](./NL108.md) instead, because naming the brace is more useful than naming the file.
