# NL353: choose the async iterator cancellation token

When an `async func*` declares more than one `CancellationToken`, the compiler cannot infer which
parameter should receive the token passed to `GetAsyncEnumerator` by `await foreach` or a C# caller.
Mark exactly one token parameter with the BCL `[EnumeratorCancellation]` attribute.

```n#
import System.Collections.Generic
import System.Threading
import System.Threading.Tasks

async func* Read(sourceToken: CancellationToken, requestToken: CancellationToken): IAsyncEnumerable<int> { // ERROR NL353
    await Task.Delay(1, sourceToken)
    await Task.Delay(1, requestToken)
    yield 1
}
```

Select the parameter that should combine with the consumer's token:

```n#
import System.Collections.Generic
import System.Runtime.CompilerServices
import System.Threading
import System.Threading.Tasks

async func* Read(sourceToken: CancellationToken, [EnumeratorCancellation] requestToken: CancellationToken): IAsyncEnumerable<int> {
    await Task.Delay(1, sourceToken)
    await Task.Delay(1, requestToken)
    yield 1
}
```

N# links that marked parameter with the consumer token. The other `CancellationToken` parameters keep
their original values. With exactly one token parameter, N# selects it automatically and emits
`EnumeratorCancellationAttribute` in the method metadata for C# interop.

To make an operation ignore consumer cancellation, pass `CancellationToken.None` to that operation.
If a token is data that should not be linked, carry it in another type such as `string` or a small
domain-specific wrapper.
