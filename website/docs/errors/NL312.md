# NL312: this code will never run

Control has already left this function by the time it reaches this line. NL312 marks the first
statement in a block that nothing can reach, because everything before it returns or throws.

```n#
func Sign(n: int): string {
    if n > 0 {
        return "positive"
    } else {
        return "not positive"
    }

    print("done")          // ERROR NL312
}
```

```text
── [NL312] ERROR ───────────────────────────── Program.nl:8:5 ──

    8 |     print("done")          // ERROR NL312
      |     ^^^^^^^^^^^^

This code will never run — there's a 'return' or 'throw' above it

Suggestion: Remove unreachable code or restructure control flow
```

Both branches of the `if` return, which makes the `if` itself a statement that always returns —
so the `print` after it is dead. The report is on the statement's own span, not on the whole dead
region: one squiggle where the reader has to make a decision, rather than a grey block.

## Why is this an error?

Unreachable code is a disagreement between what the code says and what it does, and the two ways
that disagreement arises both matter. Either the statement is left over and should be deleted, or —
much worse — the `return` above it landed in the wrong place and the code you meant to run never
does. N# cannot tell which, so it makes you say.

## How to fix it

Delete the statement, or move it above the point where control leaves:

```n#
func Sign(n: int): string {
    print("done")
    if n > 0 {
        return "positive"
    } else {
        return "not positive"
    }
}
```

## One report per block

Only the **first** unreachable statement is reported. A block with five dead statements after a
`return` produces one NL312, on the first of them: they are one mistake, and five squiggles would
suggest five.

## What makes the rest of a block unreachable

More than a bare `return`. The check folds statements the same way the missing-return check does, so
an enclosing statement counts when every path through it leaves:

- a `return` or a `throw`;
- an `if`/`else` where **both** branches leave — as in the example above;
- a `try`, `lock`, or block statement whose own contents always leave.

A mixture works too, because leaving by exception is still leaving:

```n#
import System

func Answer(n: int): int {
    if n > 0 {
        return 1
    } else {
        throw new InvalidOperationException("no")
    }

    print("done")          // ERROR NL312
}
```

## You will often see NL006 as well

N#'s linter has its own unreachable-code rule, `NL006`, with the same message. Its terminator test
is narrower — a direct `return` or `throw` statement and nothing else — so the plainest case reports
**both** codes on the same line:

```n#
func Answer(): int {
    return 42
    print("done")          // ERROR NL312 and NL006
}
```

They are two views of one mistake, and deleting the line clears both.
