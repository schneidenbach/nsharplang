# NL307: this base chain closes on itself

Following a class's base clause has to end somewhere. When it comes back to where it started
there is no type at all: no layout to compute, no constructor chain to run, and no order in
which the CLR could load the pair.

```n#
class Employee : Manager {      // ERROR NL307
    Name: string
}

class Manager : Employee {      // ERROR NL307
    Reports: int
}
```

```text
── [NL307] ERROR ───────────────────────────── Program.nl:1:7 ──

    1 | class Employee : Manager {      // ERROR NL307
      |       ^^^^^^^^

'Employee' inherits from itself: Employee -> Manager -> Employee

Suggestion: A base chain must end. Break the cycle — drop one of the `:` clauses, or make one of the links an `interface`, which may be implemented by anything on the chain.

── [NL307] ERROR ───────────────────────────── Program.nl:5:7 ──

    5 | class Manager : Employee {      // ERROR NL307
      |       ^^^^^^^

'Manager' inherits from itself: Manager -> Employee -> Manager

Suggestion: A base chain must end. Break the cycle — drop one of the `:` clauses, or make one of the links an `interface`, which may be implemented by anything on the chain.
```

**Every class in the cycle is reported, and each prints its own rotation of the chain.** That is
deliberate: each declaration is independently impossible, and there is no principled reason to
call one of them the culprit — the cycle only exists because *both* were written.

## Why is this an error?

A type's layout is its base's layout plus its own fields, and its constructor runs its base's
constructor first. Both are defined by recursion down the base chain, and both need that
recursion to terminate. Before this check existed, N# accepted the declaration through analysis
and the columnar backend refused it later with [NL103](./NL103.md) carrying no code and no line
— a message about the compiler rather than about the program.

## How to fix it

**Break the chain.** One of the two is the real base; the other is not:

```n#
class Person {
    Name: string
}

class Employee : Person {
    Title: string
}

class Manager : Employee {
    Reports: int
}
```

**Or make one link an interface.** Interfaces do not form a base chain — any number of types may
implement one, including types elsewhere on the chain — so a mutual relationship that has to
exist can be expressed as one:

```n#
interface Reporting {
    func Reports(): int
}

class Employee {
    Name: string
}

class Manager : Employee, Reporting {
    func Reports(): int {
        return 3
    }
}
```

## Cycles of any length, and self-inheritance

The walk follows the chain to a depth of 24, so a three-class cycle is caught as surely as a
two-class one, and each class prints the full route back to itself:

```text
'A' inherits from itself: A -> B -> C -> A
'B' inherits from itself: B -> C -> A -> B
'C' inherits from itself: C -> A -> B -> C
```

`class A : A` is the degenerate case and reads `'A' inherits from itself: A -> A`.

## What NL307 does not report

- **A class that merely inherits from a broken pair.** The cycle belongs to the declarations that
  close it, and each of those reports it. A class hanging off the side of one says nothing.
- **A base that did not resolve.** A chain computed from a name nobody could find is not a chain;
  that is [NL201](./NL201.md)'s report.
- **A chain the compiler cannot read all the way.** If any link's shape cannot be opened, the walk
  answers "cannot tell" rather than reporting from half a chain.
