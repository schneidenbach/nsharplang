# NL936: no source files to build

`nlc build` compiles your **product**. Files named `*.tests.nl` belong to `nlc test` and `nlc check`:
they are never emitted into the output assembly, in the same way `go build` ignores `_test.go`. So a
project whose only sources are test files has nothing for `nlc build` to produce, and a project with
no `.nl` file at all has nothing either. Both are reported here, with different wording.

This diagnostic describes the project, not a line of source, so there is no `n#` example to run. This
output is real, produced by `nlc build` over a library containing only `T.tests.nl` by
`tests/native/cli-command-contracts/TestSourceContracts.tests.nl`:

```text title="NL936 build output"
-- ERROR --------------------------------------------------  code

No source files to build

This project contains only test files (*.tests.nl), which `nlc build` does not compile.

Suggestion: Run `nlc test` to run them or `nlc check` to type-check them, or add a non-test .nl file.

Read more: https://schneidenbach.github.io/nsharplang/docs/errors/NL936
```

A project with no `.nl` file at all reads:

```text
No source files to build

This project has no .nl source files, so there is nothing to compile.

Suggestion: Add a .nl file next to project.yml, or check the `exclude` patterns in project.yml if the files you expected are being skipped.
```

## How to fix it

- If the project is only tests, run them with `nlc test`, or type-check them with `nlc check`. Neither
  needs a product to exist.
- If you meant to build something, add a non-test `.nl` file next to `project.yml`.
- If the files exist but are skipped, look at the `exclude:` patterns in `project.yml`.
