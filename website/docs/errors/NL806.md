# NL806: no constructor takes this many arguments

`new` runs a constructor, and a constructor has a fixed shape. Passing a number of arguments no
declared constructor accepts means there is nothing for the call to run.

```n#
class Point {
    X: int

    constructor(x: int) {
        X = x
    }
}

func Make(): Point {
    return new Point(1, 2)      // ERROR NL806
}
```

```text
── [NL806] ERROR ─────────────────────────── Program.nl:10:16 ──

    10 |     return new Point(1, 2)      // ERROR NL806
       |                ^^^^^

'Point' has no constructor taking 2 arguments

Suggestion: 'Point' declares one constructor: `constructor(x: int)`. Match it, or add a constructor taking 2 arguments.
```

The suggestion **spells out the constructors that exist**, so the fix is a comparison rather than
a hunt back through the declaration. With more than one, all of them are listed.

## Why is this an error?

The count decides whether there is a constructor to check the argument *types* against at all —
so this report comes first, and the type checks follow once the call fits something. Before it
existed, a wrong-arity `new` reached the columnar backend and died there as [NL103](./NL103.md),
naming a `return expression` rather than the constructor.

## A class with no constructor has exactly one

If a class declares no constructor at all, the CLR gives it a parameterless one — and that is the
only way to construct it:

```n#
class Empty {
    X: int
}

func Make(): Empty {
    return new Empty(1)         // ERROR NL806
}
```

```text
── [NL806] ERROR ──────────────────────────── Program.nl:6:16 ──

    6 |     return new Empty(1)         // ERROR NL806
      |                ^^^^^

'Empty' declares no constructor, so it takes no arguments — 1 argument passed

Suggestion: Write `new Empty()`, or declare `constructor(...)` on 'Empty' if it is meant to take arguments.
```

`new Empty()` is fine, and so is `new Empty { X: 1 }` — an object initializer runs the same
parameterless constructor and then writes the members.

## Overloads and defaults

Constructors are checked as a **set**: a call fits if it fits any one of them.

```n#
class Point {
    X: int
    Y: int

    constructor(x: int) {
        X = x
        Y = 0
    }

    constructor(x: int, y: int) {
        X = x
        Y = y
    }
}

func Make(): Point {
    return new Point(1, 2)
}
```

A **defaulted parameter** widens the accepted range rather than fixing it: `constructor(text:
string = "hi")` accepts both zero and one argument. A `params` parameter removes the upper bound
entirely.

## What NL806 does not report

- **A sized array.** `new Point[](4)` creates four slots and calls no constructor.
- **A union case.** `new Result.Success { ... }` has its own rules, and its own diagnostics.
- **A SoA table.** Its single capacity argument belongs to [NL321](./NL321.md).
- **A type from another assembly.** External constructors go through overload resolution, which
  reports [NL402](./NL402.md) when nothing matches.
- **A class with a primary constructor** — `class Point(x: int)`. Its accepted arity is a range
  that depends on parameter defaults the declaration model does not yet carry, and reporting from
  half a model would accuse correct programs. It is left silent on purpose.
