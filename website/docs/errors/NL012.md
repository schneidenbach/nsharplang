# NL012: a parameter is never read

A parameter the body never mentions is an error, for the same reason an unused local is: it is a
promise the signature makes and the code does not keep. Callers read a parameter list as a
description of what the function depends on, so a parameter nothing depends on misleads every one
of them. When the signature is fixed by an interface or an override, the `_` prefix says so.

```n#
func Greet(name: string, times: int): string {          // ERROR NL012
    return "hello " + name
}
```

```text
── [NL012] ERROR ──────────────────────────── Program.nl:1:26 ──

    1 | func Greet(name: string, times: int): string {          // ERROR NL012
      |                          ^^^^^

Parameter 'times' in 'Greet' is never read — is it needed?

Suggestion: If the parameter is required by an interface or override, prefix with '_' to suppress this: '_times'
```

The squiggle lands on the parameter name inside the signature, not on the call sites — the
declaration is what has to change.

## Why is this an error?

An unused parameter is a lie about coupling. Someone reading `Greet(name, times)` will pass a value
for `times` and expect it to matter; someone maintaining `Greet` will preserve it through a
refactor because it looks load-bearing. Neither of them can tell from the signature that the body
ignores it.

The other half of the reason is that the honest cases are common and N# has to keep them cheap.
Interface implementations, overrides, and event handlers all inherit a shape they did not choose.
That is what `_` is for, and the diagnostic says so in its own suggestion rather than making you
look it up.

## How to fix it

Drop the parameter and fix the call sites, or — when the signature is not yours to change — mark it
deliberately unused:

```n#
func Greet(name: string, _times: int): string {
    return "hello " + name
}
```

## What counts as a use

- **A read anywhere in the body**, including inside an interpolated string hole.
- **A write counts too.** A parameter that is only assigned to — `times = 1` and nothing else — is
  accepted, even though nothing reads it. As with [NL001](./NL001.md), the rule measures whether the
  name is mentioned again, not whether a value is read out of it.
- **`_` and every `_`-prefixed name are exempt.** This is the opt-out the suggestion points at.
- **Implementing an interface does not exempt you.** A method that satisfies an `interface`
  declaration is still reported for a parameter it ignores:

```n#
interface Greeter {
    func Greet(name: string, loud: bool): string
}

class Plain : Greeter {
    func Greet(name: string, loud: bool): string {   // NL012 on `loud`
        return "hi " + name
    }
}
```

  That is deliberate. The compiler cannot tell an inherited shape from a forgotten one, and guessing
  wrong in the silent direction is how unused parameters accumulate. Renaming it `_loud` records the
  judgement in the source, where the next reader can see it.

`// nlc:ignore NL012` on the line above the declaration silences one signature.
