# NL415: a type called like a function

The name before the parenthesis is a **type**, not a function. N# makes an instance with `new`. A
type name followed straight by `(...)` is not a constructor call, so nothing is created and nothing
is called.

```n#
class Widget {
    Label: string = "field"
}

func main() {
    w := Widget()              // ERROR NL415
    print w
}
```

```text
── [NL415] ERROR ──────────────────────────────── App.nl:6:10 ──

    6 |     w := Widget()              // ERROR NL415
      |          ^^^^^^

`Widget` is a type, not a function, so it cannot be called

Suggestion: N# creates an instance with `new`: write `new Widget()`.
```

This is the mistake people coming from Go, Kotlin, Swift, Python or F# make most often, because in
those languages calling a type *is* how you make one. The same report covers every kind of type:
classes, structs, records, generic types (`Box<int>()`, `List<string>()`) and types from referenced
assemblies (`StringBuilder()`, `Console()`).

## How to fix it

The suggestion depends on what the type is, because `new` only works for a type that can be
created:

| You wrote | The type is | Write instead |
|-----------|-------------|---------------|
| `Widget()`, `Point(1.0, 2.0)`, `Box<int>()` | a class, struct or record | `new Widget()`, `new Point(1.0, 2.0)`, `new Box<int>()` |
| `int(value)` | a built-in type | a cast: `(int)value` |
| `Console()`, `Math()` | a static class | one of its members: `Console.WriteLine(...)` |
| `Color()` | an enum | a member, `Color.Red`, or a cast, `(Color)value` |
| `Outcome()` | a union | one of its cases: `new Outcome.Win(...)` |
| `IShape()` | an interface | `new` on a type that implements it |
| `Shape()` | an abstract class | `new` on a type derived from it |
| `Func<int, int>(f)` | a delegate type | assign a function or lambda to a variable of that type, or `new Func<int, int>(f)` |

```n#
func main() {
    w := new Widget()
    print w
}
```

## What is *not* NL415

A **newtype** is the one type you *do* build by calling its name, because a newtype wraps a single
value:

```n#
type UserId = newtype int

func Lookup(): UserId {
    return UserId(5)           // fine: newtype construction
}
```

Calling a **value** whose type is a delegate is also fine. That is calling a function held in a
variable, not calling a type:

```n#
import System

func Apply(handler: Func<int, int>): int {
    doubler := (x: int) => x * 2
    return handler(1) + doubler(2)   // fine: both are delegate values
}
```

## Why is this its own code?

Because the fix is different from the neighbouring codes. [`NL412`](./NL412.md) means the name
resolved to nothing, so you need to define or import something. [`NL413`](./NL413.md) means a
member resolved to a value, so the parentheses are the mistake. NL415 means the name resolved to a
type: the type is right, and you need `new` (or a member of the type) instead of a call.
