# NL331: a local function reading the enclosing function's `ref`, `out` or `in` parameter

A local function that reads or writes a binding of the function around it **captures** that binding:
the binding moves into a closure object that the local function reaches through its own receiver, so
that the local function and the enclosing body share one storage location. A `ref`, `out` or `in`
parameter is not storage — it is a pointer into the **caller's** frame, which the closure object
would outlive. NL331 reports the read, because there is no lowering that could be both safe and
faithful. C# refuses the same program, as CS1628.

```n#
func Accumulate(values: int[], ref total: int) {
    func add(value: int) {
        total = total + value        // ERROR NL331
    }

    for value in values {
        add(value)
    }
}
```

```text
── [NL331] ERROR ─────────────────────────────── Program.nl:3:9 ──

    3 |         total = total + value        // ERROR NL331
      |         ^^^^^

'total' is a 'ref', 'out' or 'in' parameter of the enclosing function, so a local function cannot use it

Suggestion: Copy 'total' into an ordinary local before the local function, use that local inside it,
and assign the result back to 'total' afterwards.
```

## How to fix it

**Capture a copy, and write the result back.** An ordinary local can be captured, so the local
function accumulates into that and the `ref` parameter is assigned once, after the work is done.

```n#
func Accumulate(values: int[], ref total: int) {
    running := total

    func add(value: int) {
        running = running + value
    }

    for value in values {
        add(value)
    }

    total = running
}
```

**Or pass the value as a parameter and return the result.** A local function that takes what it needs
captures nothing at all, and stays a plain static method.

```n#
func Accumulate(values: int[], ref total: int) {
    func add(running: int, value: int): int {
        return running + value
    }

    for value in values {
        total = add(total, value)
    }
}
```

## Where the rule applies

- It applies to every use of the parameter inside the local function's body — a read, a write, or
  passing it on as an argument — and it applies through nested local functions: an inner one may not
  read an outer function's byref parameter either.
- It does **not** apply to the local function's own `ref`/`out`/`in` parameters. Those are its own
  frame's, and using them inside its body is ordinary.
- It does **not** apply to a byref parameter used in the enclosing body itself, before or after the
  local function. Only the capture is refused.
- A local function that captures nothing is still lowered as a plain method, so this rule never
  changes what a capture-free local function may do.
