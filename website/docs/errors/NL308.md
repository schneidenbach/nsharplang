# NL308: this member is not exported from its package

N# has two visibility levels and you choose between them by **capitalisation**. A `PascalCase`
member is public — visible everywhere. A `camelCase` member is package-private: visible to every
file in its own namespace, and to nothing outside it. NL308 is what you get when code in another
package reads a `camelCase` member.

The rule is a *package* boundary, not a file boundary. Two files in the same namespace see each
other's `camelCase` members freely; this example needs two files because there is no other way to
have two packages.

```n#
// FILE Lib.nl
namespace Weather.Internals

class Station {
    Name: string
    readingCount: int

    constructor(name: string) {
        Name = name
        readingCount = 0
    }
}
```

```n#
// FILE Program.nl
namespace Weather.Report

import Weather.Internals

func Describe(station: Station): string {
    return station.Name + " " + station.readingCount.ToString()          // ERROR NL308
}
```

```text
── [NL308] ERROR ──────────────────────────── Program.nl:7:41 ──

    7 |     return station.Name + " " + station.readingCount.ToString()          // ERROR NL308
      |                                         ^^^^^^^^^^^^

'readingCount' is not exported from package/namespace 'Weather.Internals' — use PascalCase for cross-package visibility or keep camelCase members inside the declaring package
```

The message names the package the member belongs to, because that — not the file — is the boundary
that was crossed.

## Why is this an error?

Without a visibility rule, every field of every type is part of its public contract, and you find
out which parts callers depend on only when you try to change one. N# makes the choice a property
of the name so it is visible at the declaration and at every use: you can tell from
`station.readingCount` alone that you are reaching into something that was not offered to you.

Making it *capitalisation* rather than a `public` keyword is the same decision Go made, and it has
the same consequence — publishing a member is a rename, so it is a deliberate edit rather than a
one-word afterthought.

## How to fix it

**Export it**, if callers outside the package are meant to have it. Rename to PascalCase:

```n#
// FILE Lib.nl
namespace Weather.Internals

class Station {
    Name: string
    ReadingCount: int

    constructor(name: string) {
        Name = name
        ReadingCount = 0
    }
}
```

```n#
// FILE Program.nl
namespace Weather.Report

import Weather.Internals

func Describe(station: Station): string {
    return station.Name + " " + station.ReadingCount.ToString()
}
```

**Or offer a method instead**, if the field itself should stay internal — the usual answer when the
member is a representation detail rather than part of the idea:

```n#
// FILE Lib.nl
namespace Weather.Internals

class Station {
    Name: string
    readingCount: int

    constructor(name: string) {
        Name = name
        readingCount = 0
    }

    func Summary(): string {
        return Name + " " + readingCount.ToString()
    }
}
```

**Or move the caller into the package.** A file that declares `namespace Weather.Internals` is
inside the boundary and needs no change at either end.

## What the boundary is, exactly

- **The namespace, not the file.** A `camelCase` member is readable from any file that declares the
  same namespace. This is worth stating because the rule is often described as "file-private" —
  it is not.
- **The declaration's own name decides.** There is no `public` or `private` keyword to disagree with
  the casing, so a member cannot be public in one place and private in another.
- **It applies to every member kind** — fields, properties and functions alike.
- **Types follow the same rule.** A `camelCase` type is package-private; a caller outside its
  package cannot name it at all, which is reported as a missing type rather than as NL308.
