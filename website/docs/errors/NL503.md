# NL503: a pattern that names something the type does not have

The pattern is well-formed syntax that does not describe anything in the type it is matched against.
NL503 is the union and property-pattern rule: it fires when a pattern names a case, or a property of
a case, that the declaration does not have.

```n#
union Shape {
    Circle { radius: double }
    Square { side: double }
}

func Describe(shape: Shape): string {
    return match shape {
        Shape.Circle { diameter: _ } => "circle",          // ERROR NL503
        _ => "other"
    }
}
```

```text
── [NL503] ERROR ──────────────────────────── Program.nl:8:24 ──

    8 |         Shape.Circle { diameter: _ } => "circle",          // ERROR NL503
      |                        ^^^^^^^^

Union case 'Circle' doesn't have a property named 'diameter' — check the case definition for available properties
```

The caret is on the offending **name** — `diameter` — rather than on the arm, so a pattern with
several properties tells you which one is wrong.

## Why is this an error?

A property pattern compiles to a read of that property followed by a test. A name the declaration
does not have has no field to read and no accessor to call, so there is nothing to lower. Guessing
the intended member — `diameter` for `radius`, say — would make one arm test a value you never asked
about.

## How to fix it

Use the name the case actually declares:

```n#
union Shape {
    Circle { radius: double }
    Square { side: double }
}

func Describe(shape: Shape): string {
    return match shape {
        Shape.Circle { radius: _ } => "circle",
        _ => "other"
    }
}
```

## The four shapes that report NL503

They are worth listing because they read alike and have different fixes:

**A case the union does not declare.** The caret covers the whole qualified name:

```n#
        Shape.Oval { radius: _ } => "oval",          // ERROR NL503
```

reading `'Shape.Oval' is not a case of union 'Shape' — check the union definition for available
cases`.

**A property the case does not declare** — the example above.

**A case that carries no data, destructured anyway.** A union case declared without a payload has
nothing to take apart, so `Option.None { value: _ }` reports rather than matching vacuously. Match it
by name alone: `Option.None => ...`.

**A property pattern against an ordinary type** that has no such member — `{ Depth: 0 }` on a class
with no `Depth`. Same code, same reason; only the message's subject changes.

## What NL503 is not

If the pattern is not valid **syntax** — a floating-point literal in a property-pattern position, for
instance — the parser reports [NL103](./NL103.md) first and NL503 follows it as a consequence. Fix
the syntax and both go away.

If the pattern is well-formed and names real members but simply cannot match this type, that is
[NL504](./NL504.md) or [NL506](./NL506.md) instead: NL503 is about names that do not exist, not about
tests that can never succeed.
