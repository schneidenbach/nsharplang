# NL931: a `[MethodImpl]` value that is not a `MethodImplOptions` combination

`[MethodImpl(...)]` writes its argument into a method's implementation flags, one bit per
`MethodImplOptions` member. A value with a bit **no member defines** asks for an option the runtime
does not have, so it cannot mean what it was written to mean.

```n#
import System.Runtime.CompilerServices

class Report {
    [MethodImpl(1024)]                              // ERROR NL931
    func Render(): string {
        return "ok"
    }
}
```

```text
── [NL931] ERROR ────────────────────────── Program.nl:4:17 ──

    4 |     [MethodImpl(1024)]                              // ERROR NL931
      |                 ^^^^

'[MethodImpl]' was given 0x400, which is not a combination of 'MethodImplOptions' values

Suggestion: Name the options you mean, for example 'MethodImplOptions.AggressiveInlining | MethodImplOptions.NoOptimization'.
```

The bits are reported in hexadecimal because that is how the option values are written down:
`AggressiveInlining` is `0x100`, `AggressiveOptimization` is `0x200`, and `0x400` — the value above —
is nothing at all.

## How to fix it

Name the options. The spelling that cannot go wrong is the enum's own:

```n#
import System.Runtime.CompilerServices

class Report {
    [MethodImpl(MethodImplOptions.AggressiveInlining | MethodImplOptions.AggressiveOptimization)]
    func Render(): string {
        return "ok"
    }
}
```

Both the short form and the fully qualified
`System.Runtime.CompilerServices.MethodImplOptions.NoInlining` are accepted, and so is a `|`
combination of any number of them.

A member whose name is not an option of the enum is reported as an undefined member (`NL303`) rather
than here, and an argument that is not a compile-time constant at all is reported as `NL310`.
