# NL103: this construct cannot be compiled

N# understood your program and could not turn it into IL. NL103 is the backend's refusal, not the
parser's: the syntax is legal, the types check, and the code generator has no lowering for the shape
it was handed. The message names the exact site with an internal reason string.

```n#
class Box {
    Value: int
}

func Describe(b: Box): string {
    return b.ToString() ?? ""          // ERROR NL103
}
```

```text
── [NL103] ERROR ──────────────────────────── Program.nl:6:12 ──


Columnar emission is required for 'PNL103', but the columnar backend declined. Declined at emit.return.expression: return expression could not be emitted in 'Describe' (Program.nl:6:12).

This product path requires successful N# columnar emission after analysis passes.

Suggestion: Port the rejected source shape to the columnar backend before using this product path.
```

Read the decline site — here `emit.return.expression` — as "the code generator gave up in a return
expression, in this function, at this line". That is the shape to change.

## Why is this an error?

The alternative is worse. A backend that skipped what it could not lower would produce an assembly
missing part of your program, and you would find out at run time. N# refuses the build instead, and
names the position precisely enough to work around.

## How to fix it

Split the expression so each step is a shape the backend does lower. Introducing a local is almost
always enough:

```n#
class Box {
    Value: int
}

func Describe(b: Box): string {
    text := b.ToString()
    if text == null {
        return ""
    }

    return text
}
```

## What NL103 is telling you

NL103 is the only code in N# that reports a *compiler* limitation rather than a mistake in your
program. Two consequences follow:

- **It is worth reporting.** A decline site that blocks reasonable code is a gap in the backend, and
  the message contains everything a bug report needs: the reason string, the function, and the
  position.
- **It moves.** Shapes that declined in one release compile in the next, so an NL103 you worked
  around is worth revisiting rather than treating as a permanent rule of the language.

A construct that is deliberately withheld from production builds is `NL323` instead —
that one is a decision, not a gap, and it says so.
