# NL413: a value that is not something you can call

The name before the parenthesis resolved to something real — a field, a property, a local or a
parameter — but to a **value**, and a value can only be called when its type is a delegate. An `int`
property, a `string` field or a record component named right before `(` is not a call target, and
there is no method or extension of that name that could have been meant instead.

```n#
class Box {
    Size: int
}

func Use(box: Box): int {
    return box.Size()          // ERROR NL413
}
```

```text
── [NL413] ERROR ──────────────────────────── Program.nl:6:16 ──

    6 |     return box.Size()          // ERROR NL413
      |                ^^^^

`Size` is a field of type `int` on `Box`, not something you can call

`Size` is called like a function on line 6, but it is a field of type `int` on `Box`:

Hint: Only a delegate value can be called. If you meant to read `Size`, drop the parentheses.
If `Size` is meant to be called, give it a delegate type such as `Func<int>`.
If you meant a method or an extension named `Size`, check its spelling and that whatever
declares it is imported.

Suggestion: Drop the parentheses to read `Size`.
```

## The same mistake without a receiver

Inside a type, a member is usually named **bare**, and the bare call is the same error with the same
sentence — `Label()` and `this.Label()` are two spellings of one mistake:

```n#
class Widget {
    Label: string = "field"

    func Show(): string => Label()        // ERROR NL413
}
```

```text
`Label` is a field of type `string` on `Widget`, not something you can call
```

A **local** or a **parameter** called like a function is reported the same way:

```n#
func Use(count: int): int {
    return count(1)                       // ERROR NL413: `count` is a value of type `int`
}
```

## A member and free function with the same bare name are NL209

At a call, a method or delegate-typed field/property can compete with a visible free-function group;
that name collision is [NL209](./NL209.md). A non-delegate field or property cannot be called, so it
does not compete: when a same-named free function is visible, the call resolves to that function.
Without one, a call to the non-delegate member remains NL413 as described above. A bare read of a
field or property can still be ambiguous with a same-named free-function group.

## Why is this its own code?

Because the fix is different from the one every neighbouring code asks for. `NL412` means the name
resolved to nothing at all and you need to *define or import* something. NL413 means the name
resolved perfectly well and the parentheses are the mistake.

The distinction also matters in the other direction. When a value **is** a delegate, calling it is
correct and nothing is reported — through a receiver, bare, or as a local:

```n#
class Button {
    OnClick: Func<int, int>

    func Fire(): int => OnClick(1)   // fine — OnClick is a delegate
}

func Use(button: Button): int {
    return button.OnClick(1)         // fine
}
```

A field-like `event` is raised the same way from inside its type (`Changed(this, EventArgs.Empty)`),
because an event's type is a delegate too.

## A member that cannot be called does not hide a method of the same name

N# resolves the name before `(` as a **call target**, which is a different question from reading the
same name as a value: a member whose value cannot be called is not a candidate at all, so a method
or an extension of that name is still found. This is what makes the most common LINQ shape in .NET
legal:

```n#
import System.Collections.Generic
import System.Linq

func CountNonEmpty(values: List<string>): int {
    return values.Count(value => value.Length > 0)
}
```

`List<T>.Count` is an `int` property and `Enumerable.Count<TSource>` is an extension method. Only the
second one is invocable, so `values.Count(predicate)` calls the extension while `values.Count` reads
the property — exactly as it does in C#.

NL413 is therefore reported only when the *value* reading is the only reading there is.

## How to fix it

Remove the parentheses when you meant to read the value:

```n#
func Use(box: Box): int {
    return box.Size
}
```

Give the member a delegate type when it really is meant to be called:

```n#
class Widget {
    Label: Func<string> = () => "computed"

    func Show(): string => Label()
}
```

Or call the member you meant — check the spelling, and check that whatever declares the method or
extension you expected is imported.
