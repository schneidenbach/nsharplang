# NL413: a member that is not something you can call

The name before the parenthesis resolved to a real member of the receiver — but to a **value**, and
a value can only be called when its type is a delegate. An `int` property, a `string` field or a
record component named right before `(` is not a call target, and there is no method or extension of
that name that could have been meant instead.

```n#
class Box {
    Size: int
}

func Use(box: Box): int {
    return box.Size()          // ERROR NL413
}
```

```text
── [NL413] ERROR ──────────────────────────── Program.nl:6:16 ──

    6 |     return box.Size()          // ERROR NL413
      |                ^^^^

`Size` is a value of type `int`, not something you can call

Suggestion: Drop the parentheses to read `Size`, or call a method or extension of that name — only a
delegate value can be called.
```

## Why is this its own code?

Because the fix is different from the one every neighbouring code asks for. `NL412` means the name
resolved to nothing at all and you need to *define or import* something. NL413 means the name
resolved perfectly well and the parentheses are the mistake.

The distinction also matters in the other direction. When a member's value **is** a delegate, calling
it is correct and nothing is reported:

```n#
class Button {
    OnClick: Func<int, int>
}

func Use(button: Button): int {
    return button.OnClick(1)   // fine — OnClick is a delegate
}
```

## A member that cannot be called does not hide a method of the same name

N# resolves the name before `(` as a **call target**, which is a different question from reading the
same name as a value: a member whose value cannot be called is not a candidate at all, so a method
or an extension of that name is still found. This is what makes the most common LINQ shape in .NET
legal:

```n#
import System.Collections.Generic
import System.Linq

func CountNonEmpty(values: List<string>): int {
    return values.Count(value => value.Length > 0)
}
```

`List<T>.Count` is an `int` property and `Enumerable.Count<TSource>` is an extension method. Only the
second one is invocable, so `values.Count(predicate)` calls the extension while `values.Count` reads
the property — exactly as it does in C#.

NL413 is therefore reported only when the *value* reading is the only reading there is.

## How to fix it

Remove the parentheses when you meant to read the member:

```n#
func Use(box: Box): int {
    return box.Size
}
```

Or call the member you meant — check the spelling, and check that whatever declares the method or
extension you expected is imported.
