# NL102: expected token

The parser needed a specific token here and found something else. Unlike [NL101](./NL101.md), which
names a token that does not belong, this one names a token that is *missing* — so the message says
what was expected, and the suggestion says exactly what to add.

```n#
func Greet(name string): string {          // ERROR NL102
    return "hello " + name
}
```

```text
── [NL102] ERROR ──────────────────────────── Program.nl:1:12 ──

    1 | func Greet(name string): string {          // ERROR NL102
      |            ^^^^

Expected ':' after parameter name. Got 'string'

Parameter 'name' needs a ':' before its type.

Hint: Write this parameter as `name: Type`.

Suggestion: Add ':' after 'name'
```

N# parameters are always `name: Type`. Without the colon the parser reads `name` as the parameter
and then finds a second bare word where the comma or the closing paren should be.

## Why is this an error?

`func Greet(name string)` is unambiguous to a human and ambiguous to a parser: it could be a
parameter `name` of a type that was never written, or a parameter `string` whose name was mistyped.
N# does not choose between them. It reports the one thing it is certain of — a colon belongs after
`name` — and points the caret at `name` rather than at `string`, because that is where you type.

## How to fix it

```n#
func Greet(name: string): string {
    return "hello " + name
}
```

## Where else NL102 appears

The code covers every "I needed this token" case, and the message always names it:

- a missing `:` in a parameter, a field, or a variable annotation;
- a missing initializer after `:=` — `x :=` with nothing after it;
- a missing `,` between `match` arms;
- a missing name after `class`, `record`, `union` or `enum`.

If the file simply ends where the token was expected, N# reports [NL104](./NL104.md) instead, since
"add a `)`" is unhelpful advice when what is actually missing is the rest of the program.
