# NL109: reserved keyword used as a name

N# has eighty-three reserved words, and a name is not one of them. This is a distinct code from
[NL101](./NL101.md) on purpose: the token is not surplus and nothing is missing — the fix is always
to rename.

```n#
class Greeter {
    Name: string

    func Rename(text: string) {
        Name = text.union          // ERROR NL109
    }
}
```

```text
── [NL109] ERROR ──────────────────────────── Program.nl:5:21 ──

    5 |         Name = text.union          // ERROR NL109
      |                     ^^^^^

Expected member name. Got the reserved keyword 'union'

'union' is a reserved keyword in N#, so it can't be used as a name here.

Hint: After a member access, the name must not be a reserved keyword. To reach a  member literally named 'union', access it through a differently-named alias.

Suggestion: Rename it to 'unionValue' or '_union'
```

The suggestion is part of the diagnostic. N# proposes both conventions it accepts, so the fix is a
copy rather than a decision.

## A reserved word used as a variable

When the word is written where an expression belongs — `out := 5`, `partial.Length` — the message is
shorter and says the one thing that matters:

```n#
func main() {
    out := 5                     // ERROR NL109
    print out.ToString()         // read as the same name: no second report
}
```

```text
'out' is a reserved word; choose another name
```

Each distinct word is reported **once per file**, at its first use as a name. Every later use of that
same word is read as that name, so the single rename is the whole fix and no error repeats down the file.

## Why is this an error?

`union`, `record`, `match`, `base`, `params` and the rest are how N# tells one construct from
another. A name that collides with one makes the surrounding code ambiguous to the parser, and —
because the parser cannot recover cleanly — it often takes the whole enclosing declaration with it.

## How to fix it

Rename, at every use:

```n#
class Greeter {
    Name: string

    func Rename(text: string) {
        Name = text.unionValue
    }
}
```

## The words that surprise people

Several reserved words read like ordinary nouns, and these are the ones that actually cost people
time: `record`, `union`, `match`, `base`, `params`, `must`, `scoped`, `required`, `alloc`, `allow`,
`partial`, `newtype`, `nameof`. A C# habit gets two more: `out` and `explicit` are keywords here too, so
`out := 5` is refused. The whole list is in [Reserved Words](../basics.md#reserved-words).

Words that look reserved and are **not**: `test`, `field`, `property`, `setup` and `teardown` are
ordinary names; `file` was the file-private type modifier and left the language with it; and `type`
is **contextual** — it opens a [type alias](../language-tour.md#type-aliases) declaration
(`type Name = Underlying`) and is an ordinary identifier in every other position, so a member, a
parameter, a local, a loop variable and a declaration may all be called `type`.

## Where the position lands

The diagnostic points to the reserved word used as a name. The parser reads later uses of that same
word as the refused name, so one NL109 does not turn the rest of the declaration into a cascade.
