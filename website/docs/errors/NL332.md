# NL332: a `yield` inside a protected region that cannot resume

A generator (`func*` / `async func*`) may suspend inside a `try` whose **only** handler is a
`finally`. It may not suspend inside a `try` that declares a `catch`, and it may not suspend inside a
`catch` or `finally` handler at all. NL332 reports each of those three placements.

The rule follows from what suspension is. A `yield return` hands control back to whoever is
enumerating — an arbitrary amount of code runs, on an arbitrary thread, before `MoveNext` is called
again — so the compiler has to be able to *leave* the protected region and then *re-enter* it at the
same point later. Leaving and re-entering a `try`/`finally` is expressible: the `finally` is skipped
on the way out (the machine is suspended, not finished) and runs when the enumeration ends, whether
that is by completion, by an exception, or because the consumer stopped early and called `Dispose`.
A `catch` cannot be re-armed that way — the frames it guards are gone the moment control returns to
the caller — and a handler body may not be suspended out of and resumed back into at all.

```n#
import System
import System.Collections.Generic

func* Rows(): IEnumerable<int> {
    try {
        yield 1                       // ERROR NL332
    } catch e: Exception {
        print e.Message
    }
}
```

```text
── [NL332] ERROR ────────────────────────────────── Program.nl:7:9 ──

    7 |         yield 1                       // ERROR NL332
      |         ^^^^^

A 'yield' cannot appear inside a 'try' that declares a 'catch'

Suggestion: A generator may only suspend inside a `try` whose only handler is `finally`. Move the
`catch` to a wrapping function, or move the `yield` out of this `try`.
```

## How to fix it

**Keep the `finally` and drop the `catch`.** A `try`/`finally` around a `yield` is fully supported,
and it is what most cleanup wants: the handler runs when the enumeration completes, when an exception
passes through, and when a consumer abandons the enumeration part-way.

```n#
func* Rows(log: List<string>): IEnumerable<int> {
    try {
        yield 1
        yield 2
    } finally {
        log.Add("closed")
    }
}
```

**Or move the `catch` to a wrapping function.** A generator that must handle an exception around a
suspension is really two functions: one that produces the elements, and one that consumes them
inside the handler.

```n#
func* Rows(): IEnumerable<int> {
    yield 1
}

func Safe(): List<int> {
    collected := new List<int>()
    try {
        for v in Rows() {
            collected.Add(v)
        }
    } catch e: Exception {
        print e.Message
    }
    return collected
}
```

**Or move the `yield` out of the handler.** Compute the value inside the `catch` or `finally`, and
suspend after the `try` statement has finished.

```n#
func* Rows(): IEnumerable<int> {
    value := 0
    try {
        value = int.Parse("nope")
    } catch e: FormatException {
        value = 0 - 1
    }
    yield value
}
```
