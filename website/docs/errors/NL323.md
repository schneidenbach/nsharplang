# NL323: this feature is not available in production builds

NL323 is the compiler telling you that a construct it *understood* is deliberately switched off. The
syntax is real, the parser accepts it, and the analyzer has a representation for it — but the
implementation is not finished and verified, so production builds refuse it rather than emit
something unproven.

```n#
soa record Particle {          // ERROR NL323
    X: int
    Y: int
}
```

The message names the feature and, where one exists, the way to keep working: here, an ordinary
`record`.

```text
── [NL323] ERROR ───────────────────────────── Program.nl:1:1 ──

    1 | soa record Particle {          // ERROR NL323
      | ^^^

soa record 'Particle' is parsed but not available in production builds yet

Suggestion: Set NSHARP_EXPERIMENTAL_SOA=1 only for the compiler table migration gate; otherwise keep using regular records
```

## Why is this an error?

The alternative would be to accept the declaration and generate whatever the half-finished lowering
produces. A struct-of-arrays record changes the memory layout of every instance and every field
access that touches it; shipping that before the layout and its verification gates land would mean
programs that compile, run, and are wrong in ways no test in your project would catch.

NL323 is the honest answer: the feature is spelled correctly, and it is not available.

## How to fix it

Use the supported construct. For a `soa record`, that is a plain `record` — same fields, same
members, ordinary layout:

```n#
record Particle {
    X: int
    Y: int
}
```

## Where NL323 fires today

NL323 is not tied to one feature; it is the code for "recognised, deliberately withheld". The
declarations currently behind it:

**A `soa record`** — the struct-of-arrays record form, as above.

**A `skip` clause on a test.** The clause parses so that existing files keep working, but `nlc test`
cannot report a skipped test, so a file that spells it is refused:

```n#
test "adds two numbers" skip "flaky on CI" {   // reports NL323: test 'adds two numbers' declares
    assert Add(1, 2) == 3                      //  'skip', which is parsed for forward
}                                              //  compatibility but is not compiled by 'nlc test'
```

The suggestion is to delete the clause and its reason, or to comment the whole test out. There is
deliberately no "run it but mark it skipped" fallback.

**A `static` member on a generic type.** The declaration is understood and not yet lowered:

```n#
class Box<T> {
    Value: T

    static func Empty(): int {      // reports NL323: Static method 'Empty' is not supported on
        return 0                    //  generic type 'Box<T>' yet
    }
}
```

Move the member to a non-generic helper type, or make it an instance member.

## NL323 versus NL103

These two are easy to confuse and mean opposite things.

- **NL323 is a decision.** Someone looked at this construct and chose not to ship it yet. The
  message names the feature, and there is usually a supported alternative.
- **[NL103](./NL103.md) is a gap.** The backend simply has no lowering for the shape it was handed.
  The message names an internal decline site rather than a feature, and the fix is to rewrite the
  expression into a shape that does lower.

Both move between releases, so both are worth revisiting rather than treating as permanent rules of
the language.
