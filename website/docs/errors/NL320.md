# NL320: `lock` requires a reference type

The expression a `lock` statement locks on must be a reference type. Locking on a value type
— `int`, a struct, an enum, `int?`, or any other value — is a compile-time error.

```n#
func Count(n: int) {
    lock n {          // ERROR NL320: 'int' is not a reference type as required by the lock statement
        print(n)
    }
}
```

```text
This `lock` statement needs a reference type, but `int` is a value type:

3|     lock n {
            ^

Hint: `Monitor` locks on object IDENTITY. A value type has no stable identity: it would be
boxed into a fresh object on every `lock`, so no two threads would ever contend on
the same lock — the lock would guard nothing.
```

## Why is this an error?

`lock` is implemented with `System.Threading.Monitor`, which synchronizes on the *identity*
of an object reference. A value type has no stable identity — passing one where an object is
required boxes it into a **fresh object on every lock**, so two threads "locking the same
value" actually lock two different objects and never exclude each other. The lock would
compile, run, and protect nothing. N# rejects that shape.

This also applies to generic type parameters: `lock x` where `x: T` is an error unless `T`
is provably a reference type. Boxing an unconstrained `T` creates a lock that can never
provide mutual exclusion, so N# rejects the trap.

```n#
func LockIt<T>(x: T) {
    lock x { }        // ERROR NL320: 'T' is not a reference type as required by the lock statement
}

func LockRef<T>(x: T) where T: class {
    lock x { }        // OK: T is constrained to a reference type
}
```

## How to fix it

Lock on a dedicated `object` field instead — one shared instance whose identity all threads
agree on:

```n#
class Counter {
    count: int = 0
    sync: object = new object()

    func Increment() {
        lock sync {
            count++
        }
    }
}
```

For a generic type parameter, either add a reference-type constraint (`where T: class`) or
lock on a dedicated `object` field as above.
