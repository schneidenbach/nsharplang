# NL930: `[MethodImpl]` on a declaration that has no implementation flags

`[MethodImpl(...)]` is not an ordinary attribute. The CLR never stores it in the custom-attribute
table; it reads it and writes what it says into the **implementation-flags column of a method
definition row** — the column the JIT consults when it decides whether a call may be inlined, and
the one `MethodBase.GetMethodImplementationFlags()` reads back.

Only a method-like declaration has that column. A type, a field, an enum or an interface does not,
so `[MethodImpl]` written there has nowhere to go at all.

```n#
import System.Runtime.CompilerServices

[MethodImpl(MethodImplOptions.NoInlining)]          // ERROR NL930
class Report {
    func Render(): string {
        return "ok"
    }
}
```

```text
── [NL930] ERROR ─────────────────────────── Program.nl:3:2 ──

    3 | [MethodImpl(MethodImplOptions.NoInlining)]          // ERROR NL930
      |  ^^^^^^^^^^

'[MethodImpl]' sets a method's implementation flags, and a class has none

Suggestion: Move it to the method, constructor or property whose implementation it describes.
```

## Why this is an error rather than a dropped attribute

An ordinary attribute in an odd place is still recorded: the row exists, and a reader that does not
care simply never looks at it. This one is different. There is no row to write, so the declaration
would compile, say nothing, and leave you believing the method was marked. A promise the assembly
cannot record is refused rather than silently lost.

## How to fix it

Put the attribute on the member whose implementation it is talking about.

```n#
import System.Runtime.CompilerServices

class Report {
    [MethodImpl(MethodImplOptions.NoInlining)]
    func Render(): string {
        return "ok"
    }
}
```

`[MethodImpl]` is accepted on a **method**, a **free function**, a **constructor**, a **property**
and an **indexer**. On a property or an indexer it marks every accessor the declaration writes, which
is N#'s spelling of what C# writes as a per-accessor `[MethodImpl]`.
