# NL343: a write to an init-only member after the object exists

An `init` member may be set **while the object is being created** and at no other time. The two
places that counts are the **object initializer** that creates the value and a **constructor** of
the declaring type — or of a type derived from it. NL343 is every other write.

```n#
class Configuration {
    init AppName: string
}

func rename(config: Configuration) {
    config.AppName = "Other"          // ERROR NL343
}
```

```text
── [NL343] ERROR ────────────────────────── Program.nl:6:12 ──

    6 |     config.AppName = "Other"          // ERROR NL343
      |            ^^^^^^^

'AppName' is declared 'init' — it can only be set while the object is being created, so it can't be assigned with '='

Suggestion: Set 'AppName' in the object initializer that creates the value — 'new Configuration { AppName: … }' — or in a constructor of 'Configuration'. Drop 'init' from the declaration if the value is meant to change after the object exists.
```

The same rule covers `++`, `--` and the compound assignments, with the sentence naming the operator
you wrote.

## Why is this an error?

`init` is a promise a type makes to everyone who reads it: once a value of this type exists, this
member's value is the one the creation gave it. Code that holds such a value can cache it, key a
dictionary on it, or hand it to another thread without re-reading it.

The promise is not N#'s alone. It is written into the emitted metadata as
`modreq(System.Runtime.CompilerServices.IsExternalInit)` on the setter's return type — the same
marker C#, F# and VB use — so a C# caller of your assembly is held to the same rule by its own
compiler. A write N# allowed after creation would be a promise only N# broke.

## What is allowed

**The object initializer that creates the value**, which is what `init` exists for:

```n#
config := new Configuration {
    AppName: "MyApp"
}
```

**A constructor of the declaring type**, which runs before anyone can observe the value:

```n#
class Configuration {
    init AppName: string

    constructor(seed: string) {
        AppName = seed
    }
}
```

**A constructor of a derived type**, for the same reason:

```n#
class Base {
    init Tag: string
}

class Derived: Base {
    constructor(tag: string): base() {
        Tag = tag
    }
}
```

## How to fix it

**Move the value into the creation.** Usually the write you are looking at is happening later than
it needs to:

```n#
config := new Configuration {
    AppName: "Other"
}
```

**Or drop `init`,** if the member really is meant to change after the object exists. A member
written without the word is an ordinary mutable one.

## Members of referenced assemblies

A C# `init` accessor carries the same marker, and NL343 reads it. Assigning a C# record's `init`
property after construction is refused from N# exactly as it is from C#:

```n#
import CsLib

func rename(config: CsConfig) {
    config.Name = "Other"             // ERROR NL343 — the C# property is `{ get; init; }`
}
```

An ordinary `{ get; set; }` property on the same type is untouched by this rule.
