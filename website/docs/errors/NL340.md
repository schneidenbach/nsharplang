# NL340: a `throw` written as a value where nothing can say what the expression is worth

A `throw` produces **no value at all**. Writing one where a value is expected is still useful — but
only where some *other* operand already decides what the surrounding expression is worth. N# admits a
throw expression in exactly three positions, and NL340 reports it anywhere else.

```n#
import System

func Length(name: string?): int {
    n := 1 + throw new ArgumentNullException("name")     // ERROR NL340
    return n
}
```

```text
── [NL340] ERROR ────────────────────────────────── Program.nl:4:14 ──

    4 |     n := 1 + throw new ArgumentNullException("name")     // ERROR NL340
      |              ^^^^^

A 'throw' can't be used as a value here

A `throw` produces no value at all, so it can only stand where something else says what the
expression is worth: as the fallback of a `??` (`name ?? throw new ...`), as an arm of a conditional
(`ok ? value : throw new ...`), or as an expression body (`func F(): T => throw new ...`). Anywhere
else there is nothing to take the type from.
```

## The three positions that do work

**The fallback of `??`.** The left side decides the type; the fallback only has to say what happens
when the left side was null. The whole expression is worth the left side with its nullability
removed, and the flow analysis knows it:

```n#
import System

func Required(name: string?): string {
    value := name ?? throw new ArgumentNullException("name")
    return value.Trim()                 // `value` is `string`, never `string?`
}
```

**An arm of a conditional.** An arm that throws contributes nothing to the join, so the *other* arm
decides the type:

```n#
import System

func Checked(ok: bool, value: int): int {
    return ok ? value : throw new InvalidOperationException("not ready")
}
```

**An expression body** — an arrow-bodied `func`, an arrow-bodied property, or a lambda's. The
declared return type is what the body would otherwise have produced:

```n#
import System

func NotDone(): string => throw new NotImplementedException()

func Rejector(): Func<int, string> {
    return x => throw new NotSupportedException("no")
}
```

## How to fix it

**Make it a statement.** This is almost always what was meant — a `throw` on a line of its own needs
no type at all:

```n#
import System

func Length(name: string?): int {
    if name == null {
        throw new ArgumentNullException("name")
    }

    return 1 + name.Length
}
```

**Or move it into one of the three positions.**

```n#
import System

func Length(name: string?): int {
    return 1 + (name ?? throw new ArgumentNullException("name")).Length
}
```

## Parentheses do not help

`x ?? (throw e)` is the same mistake as `1 + throw e`. The parentheses are what the `throw` is
standing in, and a parenthesised expression has no type of its own to give it:

```n#
import System

func Required(name: string?): string {
    return name ?? (throw new ArgumentNullException("name"))     // ERROR NL340
}
```

Remove the parentheses: `name ?? throw new ArgumentNullException("name")`.
