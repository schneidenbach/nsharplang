# NL328: a field initializer cannot reach the instance

An instance field initializer runs at the **very start of every constructor**, ahead of the
base constructor call. At that moment the object is not yet an object: its base half has not
run and none of its own members has been set up. So an initializer may not name any part of
the instance — not `this`, not `base`, and not a bare instance field, method or property of
the type it is declared in.

```n#
class Animal {
    Legs: int = 4
}

class Dog: Animal {
    Name: string = "rex"
    Greeting: string = Name + " says hi"     // ERROR NL328
    Tag: int = this.Legs                     // ERROR NL328
    Size: int = Measure()                    // ERROR NL328

    func Measure(): int => Legs * 2
}
```

```text
── [NL328] ERROR ───────────────────────────── Program.nl:7:24 ──

    7 |     Greeting: string = Name + " says hi"     // ERROR NL328
      |                        ^^^^

A field initializer cannot use 'Name'

`Name` names part of the object being built, and the initializer of `Greeting` runs before
that object exists:

Hint: Field initializers run at the very start of every constructor, ahead of the base
constructor call, so nothing on the instance has been set up yet — a value read there would
be the type's default and an instance method called there would see a half-built object.

Suggestion: Assign `Greeting` in a constructor, where the object is built, or make `Name`
static.
```

## How to fix it

**Move the work into a constructor.** The object exists once the constructor body runs, so
every member — including inherited ones — is readable there.

```n#
class Dog: Animal {
    Name: string = "rex"
    Greeting: string
    Tag: int
    Size: int

    constructor() {
        Greeting = Name + " says hi"
        Tag = Legs
        Size = Measure()
    }

    func Measure(): int => Legs * 2
}
```

**Or make what the initializer needs `static`.** A static member belongs to the type, not to
the object, so it is available before any object exists.

```n#
class Dog: Animal {
    static DefaultName: string = "rex"
    Greeting: string = DefaultName + " says hi"
}
```

## Where the rule applies

- **Static field initializers are exempt.** They run in the type initializer, where there is
  no instance to reach at all. A `static` initializer may freely call the type's static
  methods and read its earlier static fields.
- **Primary-constructor parameters are not members.** `class Box(value: int) { Doubled: int =
  value * 2 }` is fine: `value` is a constructor parameter, available before the object is.
- **Lambda parameters shadow.** `Pick: Func<int, int> = x => x + 1` is fine even in a type
  that declares a field called `x`; the `x` inside the lambda is the parameter.

## Why the order is what it is

Running initializers before the base constructor is the C# order, and it is the order that
makes a base constructor see the derived state a virtual call reaches. The alternative — base
first, then initializers — would let a base constructor observe a derived field that its own
initializer has not yet written. N# keeps C#'s order and, like C#, refuses the initializers
that could notice.
