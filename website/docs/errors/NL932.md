# NL932: a `MethodImplOptions` combination the CLR will refuse

Some implementation flags are legal on their own and illegal on the member they were written on. The
CLR decides that when it **loads the type**, which means the failure arrives as a `TypeLoadException`
the first time anything touches the type — far from the line that caused it, and after a build that
said nothing.

Everything the type loader checks here is decided by the source, so N# says it at compile time
instead.

## `Synchronized` on a value type's member

`MethodImplOptions.Synchronized` makes the CLR take a monitor on the instance for the duration of
the call. A value type has no identity to lock, so the type loader refuses the whole type.

```n#
import System.Runtime.CompilerServices

struct Counter {
    count: int

    [MethodImpl(MethodImplOptions.Synchronized)]        // ERROR NL932
    func Read(): int {
        return count
    }
}
```

```text
── [NL932] ERROR ─────────────────────────── Program.nl:6:6 ──

    6 |     [MethodImpl(MethodImplOptions.Synchronized)]        // ERROR NL932
      |      ^^^^^^^^^^

'MethodImplOptions.Synchronized' cannot be carried by this member — the CLR takes a monitor on the instance, and a value type has no identity to lock, so the type loader refuses the whole type with 'Synchronized Method in Value Type'

Suggestion: Lock explicitly inside the member, or move it to a class.
```

Without this error the program compiles, and the first construction of `Counter` throws
`TypeLoadException: Synchronized Method in Value Type`.

## `InternalCall` and `Unmanaged` on a member that has a body

`MethodImplOptions.InternalCall` says the implementation lives inside the runtime itself, and
`MethodImplOptions.Unmanaged` says it is not managed code. Either way the method definition must not
carry IL. A member with a body does, and the type loader refuses it with
`Internal call method '...' with non-zero RVA`.

```n#
import System.Runtime.CompilerServices

class Clock {
    [MethodImpl(MethodImplOptions.InternalCall)]        // ERROR NL932
    func Ticks(): int {
        return 0
    }
}
```

## How to fix it

- For `Synchronized`: lock explicitly inside the member, or move the member to a `class`, which has
  the identity a monitor needs.
- For `InternalCall` / `Unmanaged`: remove the option. These describe a body that lives somewhere
  else, and a member you wrote a body for is not one of them.

The options a member with a body may carry are `AggressiveInlining`, `AggressiveOptimization`,
`NoInlining`, `NoOptimization`, `PreserveSig` and `ForwardRef`, plus `Synchronized` on a reference
type. (`ForwardRef` also describes a body elsewhere, but the type loader tolerates it on a member
that has one, so N# does not refuse it either — it is simply not useful.)
