# NL101: unexpected token

The parser reached a token that cannot appear here. Everything before it made sense; this one does
not fit the construct being read.

```n#
func Total(values: int[]): int {
    sum := 0
    for value in values {
        sum = sum + value )          // ERROR NL101
    }

    return sum
}
```

```text
── [NL101] ERROR ──────────────────────────── Program.nl:4:27 ──

    4 |         sum = sum + value )          // ERROR NL101
      |                           ^

Unexpected token ')' in expression

I was parsing an expression and found ')', which I don't know how to handle here.

Hint: Expressions can be literals (numbers, strings), identifiers, or operators. Check your syntax.
```

A stray closing delimiter is the most common cause, and it is the one N# points at directly: the
caret sits on the token that did not fit, not at the end of the statement.

## Why is this an error?

Parsing stops at the first token that cannot continue the current construct. There is no shape of
N# where `sum + value )` is a complete expression, and guessing at the intent — dropping the `)`,
or closing something that was never opened — would silently compile a program you did not write.

## How to fix it

Remove the token, or supply whatever it was meant to close:

```n#
func Total(values: int[]): int {
    sum := 0
    for value in values {
        sum = sum + value
    }

    return sum
}
```

## Related shapes that report something else

- an *unbalanced* opener rather than a stray closer is [NL106](./NL106.md), [NL107](./NL107.md) or
  [NL108](./NL108.md) — the parser names the delimiter that was never closed.
- a token that is missing rather than surplus is [NL102](./NL102.md).
- the same construct running off the end of the file is [NL104](./NL104.md).
- a reserved word where a name belongs is [NL109](./NL109.md); it looks like a stray token but has
  its own message, because the fix is to rename rather than to delete.
