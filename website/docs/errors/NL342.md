# NL342: a write to an interface's value member

An interface's **value member** — `Name: Type`, the bare spelling a class uses for its own value
members — declares a **get-only** slot: one `get_Name` accessor and nothing else. NL342 is a write
through an interface-typed receiver to one of those slots.

```n#
interface IDocumentState {
    Uri: string
}

func rename(state: IDocumentState) {
    state.Uri = "file:///b.nl"        // ERROR NL342
}
```

```text
── [NL342] ERROR ──────────────────────────── Program.nl:6:11 ──

    6 |     state.Uri = "file:///b.nl"        // ERROR NL342
      |           ^^^

'Uri' is a value member of the interface 'IDocumentState' — it is a read slot, so it can't be assigned with '='

Suggestion: An interface's value member declares a 'get' accessor and nothing else. Give 'IDocumentState' a 'func' the caller changes the value through, or write through the implementing type instead of the interface.
```

The same rule covers `++`, `--` and the compound assignments, with the sentence naming the operator
you wrote.

## Why is this an error?

The member in front of you reads like a mutable field, because in a **class** body that is exactly
what `Uri: string` is. In an **interface** the same line means something else: it opens an abstract
property slot, and the only accessor it opens is the getter.

That is a deliberate choice rather than a missing feature. N# has no body-less accessor — there is no
`{ get; set; }` to write — so a bare `Name: Type` is the only spelling an interface has for a value
member, and it has to be the spelling that *every* implementer can fill. A plain field fills a read
slot, and so does a computed get-only property:

```n#
class DocumentState: IDocumentState {
    Uri: string                       // a field fills the read slot
}

class ComputedState: IDocumentState {
    Uri: string {                     // so does a computed property
        get { return "mem://" }
    }
}
```

If the slot also demanded a setter, `ComputedState` would stop being a legal implementer — and the
mistake would not be caught here. It would be caught by the CLR, at the first use, as a
`TypeLoadException`.

## How to fix it

**Give the interface a `func` the caller changes the value through.** This is the honest shape: a
change the interface promises is a change every implementer has to be able to make.

```n#
interface IDocumentState {
    Uri: string

    func Rename(uri: string)
}

func rename(state: IDocumentState) {
    state.Rename("file:///b.nl")
}
```

**Or write through the implementing type**, when the caller already has one and the interface was
only ever the reading view:

```n#
func rename(state: DocumentState) {
    state.Uri = "file:///b.nl"
}
```

## What this rule does not cover

An interface that a **referenced assembly** declares carries its accessors in metadata, so a C#
`{ get; set; }` property really does have a setter and writing to it is ordinary mutation. NL342 is
about interfaces declared in N# source, where the slot is decided by the spelling above.
