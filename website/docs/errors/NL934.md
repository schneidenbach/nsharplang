# NL934: an attribute applied twice that does not allow multiples

An attribute type may be written more than once on the same declaration only when it says so, with
`AllowMultiple = true` in its own `[AttributeUsage(...)]`. Without that, a second application is a
duplicate the CLR's type loader refuses — and it refuses it the first time anything reads the
declaration's attributes, far from the line that caused it.

```n#
import System

class MarkAttribute: Attribute {
    constructor(tag: string) {
    }
}

class Target {
    [Mark("first")]
    [Mark("second")]            // ERROR NL934
    func Run() {
    }
}
```

```text
── [NL934] ERROR ──────────────────────────── Program.nl:11:6 ──

    11 |     [Mark("second")]            // ERROR NL934
       |      ^^^^

Attribute 'MarkAttribute' is already applied to this declaration and does not allow multiples

Suggestion: Delete the duplicate, or declare the attribute with '[AttributeUsage(..., AllowMultiple = true)]'.
```

## How to fix it

If one application was meant, delete the other:

```n#
class Target {
    [Mark("first")]
    func Run() {
    }
}
```

If the attribute is genuinely repeatable — a trait, a tag, a retry policy — say so on its
declaration, and both applications become legal:

```n#
[AttributeUsage(AttributeTargets.Method, AllowMultiple = true)]
class MarkAttribute: Attribute {
    constructor(tag: string) {
    }
}
```

## The two spellings are one attribute

`[Mark]` and `[MarkAttribute]` name the same type, so writing one of each is still a duplicate. The
count is per **declaration**: the same attribute on a function and on its parameter is two different
declarations, and neither counts against the other.
