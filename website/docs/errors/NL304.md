# NL304: used before it is assigned on every path

N# will not let you read a value that does not exist yet. A local declared without an initializer,
or a non-nullable field with no default, has to be assigned on **every** path that reaches its first
use — not on the path you had in mind. NL304 reports the paths where nothing was assigned.

```n#
func Classify(n: int): string {
    let label: string
    if n > 0 {
        label = "positive"
    }

    return label          // ERROR NL304
}
```

```text
── [NL304] ERROR ──────────────────────────── Program.nl:7:12 ──

    7 |     return label          // ERROR NL304
      |            ^^^^^

'label' is used here before it has been assigned a value on every path that reaches this point

Suggestion: Give 'label' an initial value where you declare it, or assign it on every branch before this use.
```

The squiggle is on the **read**, not on the declaration. `let label: string` is a fine line of code;
the mistake is asking for `label`'s value when `n` was zero or negative and the `if` never ran.

## Why is this an error?

`label` is declared `string`, not `string?`, and the whole point of that distinction is that a
`string` is never null. Without this check the `n <= 0` path would hand back a null through a
non-nullable type, and every downstream `??` and null test that N# skipped on the strength of the
annotation would be skipped wrongly. The type says the value is always there, so the compiler has to
make sure it is.

## How to fix it

Give the variable a value at its declaration, so no path can miss it:

```n#
func Classify(n: int): string {
    label := "not positive"
    if n > 0 {
        label = "positive"
    }

    return label
}
```

Or cover every branch. Returning from inside the `if` works just as well, because the path that
reads an unassigned `label` no longer exists:

```n#
func Classify(n: int): string {
    if n > 0 {
        return "positive"
    }

    return "not positive"
}
```

## The other half of NL304: fields and constructors

The same code covers non-nullable **fields**, asked once per constructor. Here `Label` is left
unset:

```n#
class Counter {
    Total: int
    Label: string

    constructor(total: int) {          // ERROR NL304
        Total = total
    }
}
```

That reports `Field 'Label' is non-nullable but isn't assigned in this constructor — either assign
it here or give it a default value in its declaration`, and underlines the `constructor` keyword,
because the constructor is what has to change. Two shapes are silent, and both are silent for the
same reason — the field cannot be observed unset:

- a field with a **default value**, `Label: string = ""`;
- a **nullable** field, `Label: string?`, which is allowed to have no value because its type says so.

Static fields are never asked: the CLR zero-initializes them, so a static field has a value before
any code can read it.
