# NL309: a readonly field is assigned outside its constructor

`readonly` means the field is written once, while the object is being built, and never again. NL309
is a write that happens somewhere else. The exemption is narrow on purpose: it covers the
constructor's own body and the field's initializer, and nothing else.

```n#
class Counter {
    readonly Id: int

    constructor(id: int) {
        Id = id
    }

    func Reset() {
        Id = 0          // ERROR NL309
    }
}
```

```text
── [NL309] ERROR ───────────────────────────── Program.nl:9:9 ──

    9 |         Id = 0          // ERROR NL309
      |         ^^

Field 'Id' is readonly — it can only be assigned in a constructor

Suggestion: Move this assignment into a constructor, or remove `readonly` if the field needs to change later.
```

The squiggle is on the assigned field name, so a qualified write — `this.Id = 0` — underlines `Id`
too, not `this`.

## Why is this an error?

A `readonly` field is a promise to every reader of the type that the value they saw at construction
is the value they will see later. Code leans on that: it caches the field, it hashes on it, it hands
it out without defensive copying. A write from an ordinary method breaks the promise silently, so
N# refuses the write rather than the reasoning.

## How to fix it

If the value belongs to construction, set it there — one write, in the constructor:

```n#
class Counter {
    readonly Id: int

    constructor(id: int) {
        Id = id
    }

    func Describe(): string {
        return "counter " + Id.ToString()
    }
}
```

If the field genuinely needs to change during the object's life, then it is not readonly. Drop the
modifier rather than working around it:

```n#
class Counter {
    Id: int

    constructor(id: int) {
        Id = id
    }

    func Reset() {
        Id = 0
    }
}
```

## The cases people get wrong

**The constructor exemption does not follow you into a nested body.** A lambda written inside the
constructor is a separate body that runs later — possibly much later — so a write to a readonly
field from inside it is NL309:

```n#
import System

class Counter {
    readonly Id: int
    Reset: Action

    constructor(id: int) {
        Id = id
        Reset = () => {
            Id = 0          // ERROR NL309
        }
    }
}
```

**Structs and records are covered by the same rule.** A bare-name write inside a `struct` method —
no `this.` in front of it — is still a write to the field:

```n#
struct Point {
    readonly X: int

    constructor(x: int) {
        X = x
    }

    func Zero() {
        X = 0          // ERROR NL309
    }
}
```

**Every way of writing counts.** Compound assignment is a write, so `Id += 1` reports NL309. So does
an **object initializer**, which looks like construction but is not the constructor —
`new Counter { Id: 5 }` runs after the object exists, and reports NL309 on `Id`. Passing the field
as a `ref` or `out` argument is a write the callee would make, and gets its own sentence:
`Fill(out Id)` reports `Field 'Id' is readonly — it can't be used as a out argument`.

**`static readonly` is stricter still, and says so.** A static readonly field can only be
initialized at its declaration — not in a static method, and not in a constructor — so its message
is a different sentence: `Field 'Name' is static readonly — it can only be initialized at its
declaration`.
