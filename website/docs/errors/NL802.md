# NL802: this base class cannot be extended

`sealed` is a promise a declaration makes to everyone who reads it: *nothing extends this*. A
class that inherits from a sealed one asks the compiler to break that promise, and the CLR will
not load the result.

```n#
sealed class Currency {
    Code: string
}

class Money : Currency {        // ERROR NL802
}
```

```text
── [NL802] ERROR ──────────────────────────── Program.nl:5:15 ──

    5 | class Money : Currency {        // ERROR NL802
      |               ^^^^^^^^

Cannot inherit from 'Currency' because it is a sealed class

Suggestion: Remove `sealed` from `Currency` if it is meant to be extended, or hold one instead of inheriting one — give `Money` a field `inner: Currency`.
```

The report is anchored on the **base name**, not on the deriving class's header. In a file where
several classes share one base, the base name is the word that has to change and the class
header is not.

## Why is this an error?

`sealed` is not advice. It is written into the type's metadata, and the runtime refuses to load
a type whose base is sealed — so a compiler that accepts the derivation has produced an
assembly that cannot run. Before this check existed N# accepted it in silence and the whole
project reported `ok: true`.

It is also the reason `sealed` is worth writing at all. A sealed class can be reasoned about
completely: every value of that type behaves the way the class says, with no subclass able to
change it underneath. That guarantee is only real if the compiler enforces it.

## The two ways out

**Unseal the base**, if it was only sealed out of habit and really is meant to be a base:

```n#
class Currency {
    Code: string
}

class Money : Currency {
}
```

**Or hold one instead of inheriting one.** Composition is usually what was wanted anyway, and
it works whether or not the author of the base ever intended it to be extended:

```n#
sealed class Currency {
    Code: string
}

class Money {
    inner: Currency
}
```

## Static classes

A static class is `abstract sealed` in metadata — a shape the CLR guarantees has neither
instances nor subclasses. `Math`, `Console`, `File` and `Path` are all static, and N# names them
as what the reader would call them rather than as what the metadata says:

```n#
import System

class Helpers : Math {          // ERROR NL802
}
```

```text
── [NL802] ERROR ──────────────────────────── Program.nl:3:17 ──

    3 | class Helpers : Math {          // ERROR NL802
      |                 ^^^^

Cannot inherit from 'Math' because it is a static class

Suggestion: A static class has no instances and cannot be a base. Call its members directly, as `Math.Member(...)`.
```

## What NL802 does not report

- **An interface in the base-class position.** N# writes bases and interfaces in one `:` list, so
  `class Resource : IDisposable` puts an interface where a base class would sit. That is correct
  N# and it is silent — the interface rules own it.
- **A `struct`, an `enum` or a delegate as a base.** Every value type is sealed in metadata, so
  calling one "a sealed class" would name the wrong thing. Those are a different fault with a
  different sentence.
- **A base that did not resolve.** An unknown name is [NL201](./NL201.md)'s report; NL802 never
  adds a second diagnostic about a name nobody could find.
- **A sealed class used as a value.** The rule is about the `:` clause. A field, a parameter, a
  local or a return of a sealed type is ordinary code.
