# NL105: Invalid literal

A string or character literal that the compiler cannot read as a literal. There are two families:
one where the literal never ends, and one where a backslash inside it starts no escape sequence.

## An unrecognised escape sequence

Inside a `"..."`, `$"..."` or `'x'` literal, a backslash begins an escape. If what follows it is not
one of the escapes N# knows, the compiler refuses it rather than guessing.

```n#
func main() {
    tag := "\q"        // ERROR NL105: unrecognised escape sequence `\q`
}
```

```text
-- ERROR --------------------------------------------------  Program.nl

`\q` is not an escape sequence in N#, so I cannot tell what character you meant here.

2|     tag := "\q"
              ^^

Hint: N# knows `\0 \a \b \e \f \n \r \t \v \' \" \\`, plus `\xH..HHHH`, `\uHHHH` and
`\UHHHHHHHH`.

Did you mean one of these?

    Write `\\q` for a literal backslash followed by `q`
    Use a triple-quoted `"""..."""` string, where no backslash is an escape
```

The marker covers the backslash and the character after it — the two characters you have to change.
Only the **first** bad escape in a literal is reported, because the fix for it is the fix for all of
them.

### The fix

Double the backslash, or use a raw string:

```n#
path := "C:\\temp"        // a literal backslash
path := """C:\temp"""     // a raw string has no escapes at all
```

### Watch out: some backslashes are already silently wrong

`\t` **is** a valid escape, so `"C:\temp"` is not reported — it has already become
`C:` + a tab + `emp`. NL105 can only refuse an escape that does not exist; it cannot tell you that
an escape which does exist was not the one you meant. This is why a Windows path or a regular
expression should always double its backslashes, or be written as a raw string.

### Hex escapes are refused for their width, not their letter

`\x` takes one to four hex digits, `\u` exactly four, and `\U` exactly eight. A run of the wrong
length is not a shorter escape — it is not an escape at all, and the hint says which width was
expected:

```n#
a := "\u041"          // ERROR NL105: `\u` needs EXACTLY four hex digits, as in `\u001b`
b := "\x"             // ERROR NL105: `\x` needs one to four HEX digits after it
c := "\U00110000"     // ERROR NL105: not a real code point
d := "\u0041"         // fine — the letter A
```

`\U` also refuses a lone surrogate (`\U0000D800`) and anything above `\U0010FFFF`, because those are
not scalar values. See [Escape Sequences](../language-tour.md#escape-sequences) for the full table.

## An unterminated literal

The other family: the literal opens but never closes on the line.

```n#
name := "Ada
```

```text
Unterminated string literal

2|     name := "Ada
               ^^^^

Hint: Add the closing quote on this line, or use a triple-quoted string for multi-line text.
```

Add the closing quote, or use a triple-quoted `"""..."""` string when the text really does span
lines. The same applies to character literals: `'a'` holds exactly one character, and `''` is empty.

When a literal is both unterminated *and* holds a bad escape, the unterminated diagnostic is the one
reported — the missing quote is the author's actual problem.
