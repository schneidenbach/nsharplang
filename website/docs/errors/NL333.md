# NL333: a `using` resource with no way to be released

A `using` statement exists to release its resource when the block ends. NL333 reports a resource
whose type gives it nothing to call: the type neither implements `IDisposable` nor declares a
parameterless `Dispose` member of its own. An `await using` asks the same question about
`IAsyncDisposable` and `DisposeAsync`, and says so.

A resource qualifies in either of two ways, and the compiler tries both:

- **Nominally** — the type implements `IDisposable` (or `IAsyncDisposable` for `await using`).
- **Structurally** — the type declares a parameterless `Dispose` returning `void` (or a parameterless
  `DisposeAsync`) whether or not it names the interface.

```n#
class Connection {
    func Close() {
    }
}

func Run() {
    using connection := new Connection() {      // ERROR NL333
        print "working"
    }
}
```

```text
── [NL333] ERROR ────────────────────────────────── Program.nl:7:23 ──

    7 |     using connection := new Connection() {      // ERROR NL333
      |                         ^^^

A 'Connection' is not a resource 'using' can release

`using` releases its resource by calling `Dispose()` on it when the block ends, and a `Connection`
has no such member:

Hint: A resource qualifies either nominally — it implements `IDisposable` — or structurally: it
declares a parameterless `Dispose` of its own. A `Connection` does neither, so there would be
nothing to run in the `finally`.

Suggestion: Make `Connection` implement `IDisposable`, give it a parameterless `Dispose` member, or
drop the `using` and let the value fall out of scope like any other.
```

The squiggle goes under the **resource**, not under the name you bound it to: the name is not the
mistake.

## How to fix it

**Implement the interface.** This is the fix that also makes the type usable from C# and from every
library that takes an `IDisposable`.

```n#
class Connection: IDisposable {
    func Dispose() {
    }
}
```

**Or declare the member.** N# accepts a parameterless `Dispose` structurally, so a type that is only
ever released by your own code does not have to name the interface.

```n#
class Connection {
    func Dispose() {
    }
}
```

**Or drop the `using`.** If nothing has to be released, the value can just fall out of scope.

```n#
func Run() {
    connection := new Connection()
    print "working"
}
```

## `await using` asks about a different contract

`await using` releases through `IAsyncDisposable.DisposeAsync()`. A type that implements only
`IDisposable` reports NL333 under `await using`, naming `IAsyncDisposable` — write a plain `using`
for it instead.

```n#
import System
import System.Threading.Tasks

class Client: IDisposable {
    func Dispose() {
    }
}

async func Run(): Task {
    await using client := new Client() {        // ERROR NL333
        await Task.Delay(1)
    }
}
```
