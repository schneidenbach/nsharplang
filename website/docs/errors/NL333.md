# NL333: a bare `throw` with no `catch` handler to re-throw from

A bare `throw` — the keyword with no expression after it — re-raises the exception the enclosing
`catch` handler is currently running for, **keeping its original stack trace**. It is only meaningful
where such an exception exists, so N# accepts it only inside a `catch` handler of the function it is
written in. NL333 reports the two placements where no exception is in flight.

```n#
func Load(): int {
    throw                             // ERROR NL333
}
```

```text
── [NL333] ERROR ────────────────────────────────── Program.nl:2:5 ──

    2 |     throw                             // ERROR NL333
      |     ^^^^^

A bare 'throw' can only be used inside a 'catch' handler — there's no exception here to re-throw

Suggestion: A bare `throw` re-raises the exception the enclosing `catch` is handling, keeping its
original stack trace. Outside a handler there is no such exception. Write `throw <exception>` to
raise a new one.
```

The second placement is a `finally` nested inside the handler. A `finally` runs on its own, after the
handler's frame is gone, so there is nothing left to re-raise:

```n#
import System

func Parse(): int => int.Parse("nope")

func Load(): int {
    try {
        return Parse()
    } catch e: FormatException {
        try {
            print "cleaning up"
        } finally {
            throw                     // ERROR NL333
        }
    }
}
```

```text
A bare 'throw' cannot be used inside a 'finally' nested in the 'catch' it would re-throw from
```

A nested body counts as a different function. A lambda or a local function written inside a `catch`
compiles to a method of its own, and the handler is not on *its* frame:

```n#
import System

func Parse(): int => int.Parse("nope")

func Load() {
    try {
        Parse()
    } catch e: FormatException {
        retry: Action = () => {
            throw                     // ERROR NL333 — a different method
        }
        retry()
    }
}
```

## How to fix it

**Put the bare `throw` in the handler body itself.** This is the whole point of the form: the
exception travels on with the frames it was raised in still attached.

```n#
import System

func Parse(): int => int.Parse("nope")

func Load(): int {
    try {
        return Parse()
    } catch e: FormatException {
        print e.Message
        throw
    }
}
```

**Or throw a value.** Outside a handler — or when you want a *different* exception, or want to wrap
the one you caught — name what you are raising.

```n#
import System

func Parse(): int => int.Parse("nope")

func Load(): int {
    try {
        return Parse()
    } catch e: FormatException {
        throw new InvalidOperationException("the configuration is not a number", e)
    }
}
```

Note that `throw e` is **not** the same as `throw`. Re-throwing the caught value by name raises the
same object again from the handler, which resets its stack trace to the handler's own frame — the
original failure site is lost. Reach for the bare form whenever you are not changing the exception.
