# NL504: a list pattern against a value with no list shape

A list pattern — `[]`, `[x]`, `[first, .., last]` — asks for a length and an element at an index.
NL504 says the value being matched offers neither, so there is no way to run the test.

```n#
func Describe(value: int): string {
    return match value {
        [first] => first.ToString(),          // ERROR NL504
        _ => "other"
    }
}
```

```text
── [NL504] ERROR ───────────────────────────── Program.nl:3:9 ──

    3 |         [first] => first.ToString(),          // ERROR NL504
      |         ^^^^^^^

A list pattern can only match arrays or indexable collections, but this value is 'int'
```

The type in the message is the **scrutinee's**, not the pattern's. Read it as "you wrote a list
pattern against an `int`", and the fix is usually to the `match` subject rather than to the arm.

## Why is this an error?

A list pattern lowers to a length check followed by indexed reads. An `int` has no length and no
indexer, so there is no code to generate. N# reports once, against the pattern, and then goes on
analysing the element patterns as if the element type were unknown — so one bad scrutinee produces
one diagnostic rather than one per element.

## How to fix it

Match a value that has a list shape:

```n#
func Describe(values: int[]): string {
    return match values {
        [first] => first.ToString(),
        _ => "other"
    }
}
```

If the scrutinee is right and the pattern was the mistake, use the pattern kind that fits the type —
a literal or relational pattern for a number, a property pattern for an object, a positional pattern
for a tuple.

## What counts as a list shape

Three things satisfy the check:

- **any array type**, including jagged ones — `int[]`, `int[][]`;
- the generic collections `List<T>`, `IList<T>` and `IReadOnlyList<T>`, by name;
- any **external** type whose shape matches — an `int`-typed `Count` or `Length` property with a
  getter, *and* an indexer taking exactly one `int`. Both members are searched on the type and, for
  an interface, on its inherited interfaces.

A `string` is not on that list, and this is the case that catches people out. Despite having
`Length` and an indexer, it is a primitive to N# and reports NL504:

```n#
func Describe(text: string): string {
    return match text {
        [first] => first.ToString(),          // ERROR NL504
        _ => "other"
    }
}
```

Match a `string` with literal patterns, relational patterns, or by converting it to an array first.
