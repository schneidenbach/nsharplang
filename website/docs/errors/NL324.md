# NL324: inherited abstract member is not implemented

A concrete class must supply a body for every `abstract` member it inherits. A class that
leaves one unimplemented is not an incomplete draft the compiler can finish later — it is a
type whose instances would have a slot with nothing in it.

```n#
abstract class Shape {
    abstract func Area(): double
    abstract func Perimeter(): double
    abstract Name: string => ""
}

class Circle : Shape {          // ERROR NL324
    override func Area(): double {
        return 3.14
    }
}
```

```text
`Circle` does not implement 2 inherited abstract members: `Perimeter`, `Name`:

7| class Circle : Shape {
         ^^^^^^

Hint: Implement all 2 in `Circle`, or declare `Circle` abstract so a subclass must.
```

The report is **one diagnostic naming every missing member**, not one per member. A
half-written subclass is a single mistake with a list attached; three separate squiggles on
the same class header would read as three unrelated problems.

## Why is this an error?

An `abstract` member declares a slot with no body. The CLR requires every concrete type to
fill every such slot it inherits — a type that does not is not loadable as a concrete class.
Before this check existed, N# accepted the shape and **emitted it**, so the mistake surfaced
as a runtime failure or as silently wrong behaviour rather than as a compile error.

## The two ways out

**Implement the members.** Each one needs `override`:

```n#
class Circle : Shape {
    override func Area(): double {
        return 3.14
    }

    override func Perimeter(): double {
        return 6.28
    }

    override Name: string => "circle"
}
```

**Or make the class abstract**, and pass the obligation to whoever subclasses it:

```n#
abstract class PartialShape : Shape {
    override func Area(): double {
        return 3.14
    }
}
```

## What counts as an implementation

A member of the **same name and the same kind**. A function implements an abstract function
and a property implements an abstract property — a *field* named `Area` does not implement
`abstract func Area()`, and N# reports NL324 rather than accepting it.

An implementation **anywhere between** the abstract declaration and your class discharges the
obligation. Only the nearest declaration of a name is consulted, so an intermediate class
that already overrode a member closes the slot for everything beneath it:

```n#
abstract class Shape {
    abstract func Area(): double
}

abstract class Mid : Shape {
    override func Area(): double {
        return 0.0
    }
}

class Circle : Mid {            // fine — `Mid` already implemented `Area`
}
```

## Base classes from other assemblies

The rule covers CLR base types too, through the same walk. A `class` deriving from
`System.IO.Stream` inherits ten abstract members, and all ten are named:

```n#
import System.IO

class MyStream : Stream {       // ERROR NL324: does not implement 10 inherited abstract
}                               // members: 'Flush', 'Seek', 'SetLength', 'Read', 'Write',
                                // 'CanRead', 'CanWrite', 'CanSeek', 'Length', 'Position'
```

Deriving from a **concrete** external type — `Exception`, `MemoryStream` — requires nothing
and is silent.

## When N# stays quiet

The check is deliberately conservative, and it reports nothing at all when it cannot see the
whole picture:

- a class with **no written base** — it inherits `object`, which is concrete;
- an **abstract** class, which may pass the obligation down;
- a `struct`, a `record` or an `interface` — none of them inherit an abstract class slot;
- a base clause that **did not resolve**, or any link in the base chain whose shape the
  compiler cannot open. A missing-member list computed from half a chain is not a
  missing-member list, so the whole report is abandoned rather than partially issued.
