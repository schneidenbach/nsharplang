# NL319: Control cannot leave a `finally` block

A `return` — or a `break`/`continue` that targets a loop or switch outside the `finally` —
would exit the `finally` block early. The .NET runtime must always finish running a `finally`,
whether the `try` completed normally or an exception is in flight, so the CLR forbids any
control transfer out of it (ECMA-335: a finally handler may only complete via its own end).

```n#
class Journal {
    Path: string

    func Save() {
        try {
            Append(Path)
        } finally {
            return        // ERROR NL319: control cannot leave a 'finally' block with 'return'
        }
    }

    func Append(line: string) {
        Path = Path + line
    }
}
```

```text
This `return` would leave the enclosing `finally` block:

6|         return
           ^^^^^^

Hint: Control cannot leave a `finally` block — the runtime must always finish running it,
whether the `try` completed normally or an exception is in flight.
```

## Why is this an error?

Consider what should happen when an exception is mid-flight through the `try` block and the
`finally` runs a `return`: the exception would be silently swallowed and the function would
return as if nothing happened. The CLR refuses to define that behavior — IL that branches out
of a finally handler is invalid, and a program containing it crashes with
`InvalidProgramException` on every call. N# rejects the shape at compile time instead.

The rule is about *leaving* the block:

- `return` anywhere inside the `finally` — including inside a `try`, `lock`, or `using`
  nested within it — is an error.
- `break`/`continue` are errors only when their target loop (or switch) was entered
  **outside** the `finally`. A loop opened *inside* the `finally` can `break` and `continue`
  normally.
- `throw` is always allowed: raising an exception is not a structured control transfer out
  of the handler.
- A `return` inside a lambda or local function declared in the `finally` exits that nested
  body, not the `finally` — that is legal.

## How to fix it

Move the control transfer outside the `finally`. If the `finally` needs to influence what
happens next, set a flag and act on it afterwards:

```n#
func Save(path: string): bool {
    needsRetry := false
    try {
        write(path)
    } finally {
        needsRetry = cleanupFailed()
    }
    if needsRetry {
        return false
    }
    return true
}
```
